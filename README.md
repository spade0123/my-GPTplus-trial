浮窗的问答页面位于扩展自己的来源，和网站页面隔离；仅向编程网格开放这一份界面入口，其他扩展文件不对网站开放。后台核对临时会话、来源标签、浏览器窗口和子框架身份，不能由普通网站消息启动保存。展开/收起不调用网站函数、不访问网站存储，也不取消已经进入本机后台的任务。

### 解题提示显示什么

提示正文按 **解题方向 → 对照你的代码 → 下一步 → 手算验证** 展示：具体说明算法的比较、状态更新和选择依据；指出本轮实际源码已完成什么、最关键的缺失或错误；给现在就能实现的一步和短验证输入。不能只列“核对输入、检查边界”，也不会仅凭题名套另一份代码。历史本人 AC 程序只能作参考，不能假称是官方答案或当前网页代码。

提示中新写的代码也与完整答案共用同一格式规则：不加注释，使用 `cnt+1`、`cin>>n`、`i<n` 的紧凑写法，保留缩进、换行和必要空格；说明放在代码外，多行片段使用 C++ 代码块，继续提供高亮与复制。格式要求适用于新生成的局部片段和行内示例，不改写保存的本人源码或历史回复。已有提示重新打开仍恢复原记录；需要新版格式时点击 **更新提示**，旧回复保留在本机历史中。

需要完整答案时，在提示浮窗内点击 **给出解答**。点击时重新读取并保存本次题目、完整代码与运行信息，按 **完整参考程序 → 解题思路 → 对照你的代码 → 复杂度与验证 → 原题目和样例** 显示。程序不加注释，采用 `cnt+1`、`cin>>n`、`i<n` 的紧凑写法，保留缩进、换行与 `using namespace std;` 等必要空格；解释放在程序外。原题和样例默认折叠，需要时自行展开。题面信息不全时先说明缺失，不编造程序；生成参考程序不表示已运行或 AC，也不会替换编辑器代码或提交。

提示、解答和交流中的代码块使用接近编程界面的深色背景、等宽字体和语法高亮；行内代码也采用相同配色。代码块右上角可 **复制代码**，只复制该块的原始内容，保留缩进和换行，不带标题、讲解或按钮文字。高亮不改写代码字符，不读取剪贴板，也不修改网站编辑器；剪贴板写入只由点击复制触发，扩展不新增浏览器权限。

每次点提示、解答、打开/重新打开交流或发送问题，都会重新读取当前运行区；浮窗会显示读取状态，空运行区如实标为空。再次点击解答时，把新源码、新运行信息和同题上次生成的完整解答一同交给模型，要求核对错误并修正，旧解答保留为未验证的历史参考，不当作标准答案。运行结果与当前源码的对应关系仍需核对，不能把旧运行结果冒充新测试。交流输入框和发送按钮位于上方，历史对话在下方。

打开普通提示不会自动生成完整解答；只有点击该选项才安排额外模型任务。生成期间按钮会暂时禁用，避免重复点击，完整解答与当时源码关联保存在本机，并通过 `purpose: solution` 标记纳入定期报告。重新打开提示可恢复最近一次解答，交流区域及其模型对话历史只包含普通问答。此功能复用现有交流连接，不增加浏览器权限或额外的常驻模型连接。再次生成会按新点击时的代码重新请求并使用额度；完整程序通常比简短提示耗时更长，仍先显示已生成的部分。

模型回复通过流式连接逐步显示，开头就是解题方向，不再等整份 JSON 生成结束才显示。使用 [OpenAI Codex App Server 的流式事件](https://learn.chatgpt.com/docs/app-server)，仅收到成功完成状态后才记为 complete；超时/中断会明确报错，已生成的部分仍保留。可点击浮窗内 **更新提示** 重新读取并保存当前版本；失败重试保留之前的失败与部分内容，同内容旧版完整提示升级时保留旧回复。编译器检查、本地规则和完整样例放在默认收起的辅助区，不冒充模型解法。更新前失败的提示不会自动批量重新消耗额度，打开浮窗只恢复记录，点击 **更新提示** 才重试。

仍然只在主动点击/发送时读取，不监听打字，不边写边反复调用模型。恢复历史本身不生成回复、不启动新的模型任务；用户此前已请求的后台任务可继续生成并更新状态。流式显示和任务状态轮询不会按片段重新发起模型请求；同一版本正在生成或已有本版完整提示时复用任务/结果。提示与后台完整分析是独立模型任务，会分别使用额度；Token 消耗取决于实际调用次数、发送的题面/代码长度和回复长度。提示只传本轮完整源码、题面、运行证据、必要编译信息和可靠参考，去掉重复题面与递归历史报告；完整原记录保留在本机。提示与交流各自复用本机连接进程，空闲 90 秒后退出；浮窗和当前回复使用内存，不将历史文件全量载入，不把记录写入 Chrome。实际内存与响应速度取决于页面、源码长度和服务状态，不能承诺完整答复三至五秒完成。

## 更新后显示三个按钮

1. 在 Chrome 扩展管理页重新加载本项目 extension 文件夹，确认版本为 **1.9.0**。保留原扩展身份，不卸载。
2. 回到已经打开的题目页，点击工具栏或拼图菜单中的“北大 C++ 学习教练”，更新右下角按钮。来自 1.7.x / 1.8.x 的使用者不必刷新正在写代码的题目页；原有的旧插件按钮浮层会被替换。以后新打开的 IDE 页面自动显示小按钮。
3. 旧侧栏/独立问答窗口可以关闭。点击“提示”展开统一浮窗，浮窗内点击“交流”展开对话；也可直接点击右下角“交流”快捷进入。顶部“收起”隐藏整个浮窗，快捷保存不展开浮窗。

如果从更早的、曾接管编辑器的历史版本升级，旧标签里已经执行过的历史脚本无法由更新文件撤销：先把未保存代码另存本机，再关闭并重新打开旧题目页。1.9.0 不重新启用这些脚本。

为了自动显示按钮并在点击时读到 Ace 的完整代码，扩展仅申请 **https://programming.pku.edu.cn/** 的网站权限，不申请其他网站。Chrome 没有单独的“只读 scripting 权限”；程序通过固定读取函数、消息白名单和测试限制行为，不能把它描述为浏览器强制只读。新的内容脚本仅管理自有按钮和可收起浮窗，新的后台入口仅连接这些界面和本机程序。历史 background.js / content.js / 缓存清理 / 编辑器保护 / 提交监听不进入新版执行链路。

保留 sidePanel 权限仅用于关闭 1.7.0 遗留的“点击图标自动打开侧栏”设置；没有注册 side_panel 页面，不打开侧栏。这个兼容动作只修改本扩展自己的浏览器配置，不触及题目页。真实 Chrome 升级测试已确认：旧侧栏配置可撤销，已有题目页无需导航，未保存源码及网站存储保持原样。

1.7.0 的侧栏能打开却没有获得 activeTab，导致识别不到当前题目；这个授权问题已在真实 Chrome 中复现并修复。1.8.x 使用上述单站点授权，并明确绑定来源标签和窗口，不猜测“最近活动窗口”。切换到另一题时会拒绝从旧浮窗误存，请通过新题目的按钮使用。

本地规则检查先显示，模型回复在后台生成并逐步显示；完整模型答复不承诺三至五秒完成。网站及插件自身的 Chrome 存储都不用于新代码/问题/回复的持久保存；浮窗显示内容和未发送文字仅在内存中，新记录统一写到本机 data/。storage 权限只用于下述旧插件数据迁移。

历史自动捕获提交与 AC 归档监听维持停用。已有本机时间线、AC 归档和报告保留；要记录一次修改，请主动点击快捷保存。网站原有缓存由网站自己管理，本插件不会替它清理或绕过异常。不要通过卸载或清空存储迁移旧记录。

## 将旧插件记录迁到本机

1. 重新加载本机 **1.9.0**，保留原来的扩展身份，不卸载后重装。
2. 打开提示/交流浮窗的“使用范围 → 迁出旧插件数据”，或使用“详情 → 扩展程序选项”打开独立迁移标签页。迁移页面不嵌入编程网格，也不读取任何网站页面。
3. 点击 **迁到本机并核对**，保持迁移标签页打开。每条记录先传到本机连接程序，确认文件写入、回读大小和 SHA-256 一致，再复查 Chrome 中的源记录未改变，最后只移除对应旧记录。
4. 页面显示迁移条数、本机目录及失败记录。没有可迁出的记录时会明确显示；失败、中断或源记录变化时，未获确认的原记录保留，可重试。已迁过的同内容复用本机副本。

迁出目录为项目的 **data/browser-migration/**，按原存储区域、键名哈希和内容哈希分目录保存 JSON。每份文件保留原始键名、完整原值、迁出时间和校验信息。大记录分块传送，避免本机连接单条消息大小限制；迁移不调用模型、不编译或运行程序，不生成新的 Chrome 备份，也不上传 GitHub。

范围只包含本扩展旧有的自动草稿、题面清理备份、提交关联以及编辑器来源/语言偏好，不涉及网站的 localStorage、Cookie、账号或浏览记录。旧扩展 IndexedDB 只读取已有记录并逐条迁出，不创建新的备份库。浏览器重启、扩展停用或重新加载时消失的临时 session 关联，以及此前已删除或卸载后丢失的数据，不能凭空恢复；已成功保存到本机 data/ 的源码快照另行保留。[Chrome 存储说明](https://developer.chrome.com/docs/extensions/reference/api/storage)

此入口只解决插件旧数据的位置，**不会解决编程网格自身的 QuotaExceededError**。网站存储故障需要另外备份后手动排查；本版本不自动改动网站数据。

## 在 Codex 中使用同一批记录

在 Codex 中提供题面与源码，或指定本机 C++ 文件，使用 MCP 分析、保存学习笔记及汇总既有记录。此过程不操作编程网格页面。编译检查不执行学生程序或自动提交。

**提示和交流必须结合本人本轮完整代码。** 每条诊断给实际行号或原文片段、与题意的差距、沿用当前写法的局部改法及验证方法。不会只给函数概念或不相干的完整解法。历史 AC 仅作参考，不能冒充当前代码；源码缺失、仅有模板或问题所指片段不存在时先明确说明。

通过 MCP 的 **code_help** 使用提示或交流：mode 选择 hint 或 discussion，每次明确提供完整 code、允许目录内的 file，或选定的 snapshot_id，三者只选一个；交流同时提供 question。也保留 hint_homework、discuss_homework 两个 MCP 提示模板，供支持该协议功能的客户端使用。历史快照明确标明来源，不自动当作网页当前代码。

每轮请求先将问题和冻结的完整源码写入本机 **data/code-help/**，状态为 awaiting_reply；当前 Codex 结合实际代码生成答复，再用 **save_code_help_reply** 保存真实回复，状态才变为 complete。失败时不假报已回复；重复保存同一答复不会新增副本，改写答复会保留前一版。**review_history 的 codeHelp 字段**提供这些问题、答复及状态，供定期报告分析；includeSource=true 可取回源码。代码问答按最近提问或保存答复时间筛选，较早提问的新答复仍能纳入后续报告。

没有取得源码时会要求提供代码；只有初始模板时会如实指出。新请求和回复都不写入 Chrome，不另外启动一个模型进程；本轮模型由当前 Codex 完成。

安装 MCP 时使用项目目录中的安装命令：

~~~powershell
npm ci --ignore-scripts
./install-codex.ps1
~~~

日常也可在 Codex 中直接提供源码使用 MCP，不必启用扩展。使用右下角三个按钮则需本机连接登记：新使用者在安装依赖和配置 Codex 后运行 ./install-browser.ps1，再加载 extension 文件夹；已有本机连接登记可继续使用。MCP 新工具可能需要重新连接服务后才能出现。

主要工具包括 code_help、save_code_help_reply、analyze_cpp、review_history、problem_timeline、save_review、learning_plan。代码示例使用 using namespace std;。本机定期报告只保留逐题讨论，按北京时间在原有 HTML 中追加；参考程序前保留原题、样例和本人源码。

## 已有数据

- data/：手动保存的源码快照、题面、运行证据、提示、问答及提交时间线。
- data/code-help/：新版每轮提示或交流的冻结源码、问题与真实回复。
- data/browser-migration/：从旧 Chrome 扩展迁出的原始记录；不会放入网站存储。
- archives/：对应 AC 提交的本机最终代码、README 与 debug 总结。
- reports/：项目原有报告；独立学习报告目录按原设置保留。

作业、过程源码、问答、报告和归档只保存在使用者本机，不上传 GitHub。仓库只发布工具程序、文档与必要安装包。安装者使用自己的账号、依赖和本机目录，不能取得作者的个人学习记录。

[定期报告任务说明](docs/periodic-reports.md)：只保留逐题讨论，在同一份 HTML 按北京时间追加更新，保留原题、本人源码、真实修改与问答证据、复杂度和必要参考程序。每题默认折叠，可同时展开多个；打印时展开。阅读文件夹只保留 HTML，任务状态单独保存。日程需使用者自行建立，下载代码不会自动继承作者的定时任务。
