# 北大编程网格 · VS Code C++ 学习教练

在 **VS Code 写 C++**，通过已登录的 **Chrome 连接编程网格**，直接测试、提交并查看网站返回原文；需要学习辅助时，再打开独立的 AI 提示或交流页面。

当前适配的是 `https://programming.pku.edu.cn` 的具体题目 IDE，面向 Windows 桌面版 VS Code + Chrome。项目最初计划适配 `programminggrid.pku.edu.cn`，实际核对与使用的接口位于前者。

**仓库发布工具与文档；个人题目、作业源码、对话、评测记录和报告保存在各自电脑。AI 分析会使用各自配置的模型服务与额度。**

## 日常使用

Chrome 打开题目的 `.../probset/<题集ID>/<题目ID>/ide.do` 页面，点击“编程网格 · VS Code 连接”扩展图标；`ON` 表示本机连接已建立。VS Code 打开正在编写的 `.cpp` 文件。

| 状态栏入口 | 用途 |
| --- | --- |
| 网格·评测 | 打开独立的测试、正式提交与网站原文页面。 |
| 网格·保存 | 保存点击时的代码快照及题目记录，安排后台分析。 |
| 网格·提示 | 获取简短的概念、算法方向与下一步学习建议。 |
| 网格·交流 | 围绕当前题目和代码继续提问。 |
| 按日期整理 | 预览后，将当前项目根目录的 C/C++ 源码按最后修改日期整理。 |

四个“网格”按钮固定可见。操作时会核对当前 C++ 文件；若有多个源码来源且焦点在面板，请先点击目标 `.cpp` 文件。网站判题页面不显示 AI 答复，便于专注独立解题。

### 测试代码、手工输入和正式提交

| 操作 | 发给网站的输入参数 | 返回内容 |
| --- | --- | --- |
| **测试代码 · 网格判题** | 包含 `stdin` 字段，值为空 | 与网页“测试代码”的请求一致，由网格返回测试判定及提示。 |
| 手工输入测试 | 包含 `stdin` 字段，值为填写的内容 | 云端运行该输入，输出由使用者自行核对。 |
| **正式提交到编程网格** | 省略 `stdin` 字段 | 独立的正式提交与平台评测。 |

“手工输入”入口就在两个操作按钮下方，默认关闭。样例即使填入可选输入框，也不会自动改变默认判题模式。

顶部优先显示**网站原文**，包括网站实际提供的 `Testing Input`、`Result`、`Output`、`Hint`、`Std/Out`、编译信息和用例差异；不会补造网站未提供的内容。判定使用大字完整名称和颜色，例如 Accepted、Wrong Answer、Compile Error、Time Out。页面不展示原始接口 JSON。

刷新只读取本次编号的结果，不再次上传代码。重新打开页面只恢复上次记录，不自动查询。当前操作收到结束判定和原文后停止自动查询；发送状态不确定时不会自动重发。

## 安装

准备 Node.js 22+、npm、`g++`、已登录的 Codex 可执行程序，以及 VS Code、Chrome 和自己的编程网格账号。

1. 克隆主仓库，进入项目根目录：

   ```powershell
   git clone https://github.com/spade0123/my-GPTplus-trial.git
   cd my-GPTplus-trial
   npm ci --ignore-scripts
   ```

2. 注册独立的网格本机连接：

   ```powershell
   .\install-grid.ps1
   ```

   需要时传入 `-NodePath`、`-CodexPath`、`-CompilerPath`，使用各程序的真实绝对路径。Codex 参数应指向已经登录的 `codex.exe`。连接名称为 `edu.pku.grid_vscode_coach`，安装位置需要保持可用。

3. Chrome 打开 `chrome://extensions`，开启开发者模式，加载项目的 **`extension/`** 目录。自己登录编程网格并打开具体题目 IDE，点击连接图标。

4. VS Code 执行“扩展：从 VSIX 安装”，选择 [pku-grid-cpp-coach-0.2.11.vsix](dist/pku-grid-cpp-coach-0.2.11.vsix)，然后运行 **Developer: Reload Window**。

5. 打开 C++ 文件，点击“网格·评测”。需要关联或更换题目时，使用评测页底部的“题目连接与本机记录”。

本机配置、路径和扩展身份由安装脚本生成，每位同学需要在自己的电脑安装；不要复制他人的 `native/paths.json`、连接清单或登录配置。安装脚本遇到同名连接已注册到另一目录时会停止并说明。

## 它怎样运行

```text
VS Code 当前 C++ 代码
        │ 点击测试或提交
        ▼
本机连接程序 ── Chrome 已登录会话 ── 编程网格云端
        ▲                              │
        └──── 网站判定与原文 ──────────┘
        │
        ├── VS Code 独立评测页面
        └── 本机记录

提示/交流页面 ── 本机分析进程 ── 模型服务
```

VS Code 读取点击时编辑器里的完整缓冲区，包括尚未写入文件的修改。Chrome 核对题目并通过自己的登录会话访问网站。本站的执行编号按字符串保存，支持实际返回的 32 位十六进制编号。

网站原文先返回界面，快照整理与报告处理在后台继续。测试和正式提交通过网格运行；AI 服务不承担判题。请求经过哪些阶段、结果怎样关联源码，见 [架构与数据流](docs/programminggrid-architecture.md)。

## 更新与排查

- **更新 VS Code 扩展后**：安装新 VSIX，运行 Developer: Reload Window。
- **更新 Chrome 连接代码后**：在扩展管理页重新加载连接扩展；需要时在题目页再次点击图标连接。
- **只有 VS Code 界面或本机服务更新时**：按该次更新说明操作，无需每次都重载 Chrome。当前 VS Code/本机程序和 Chrome 连接清单均为 0.2.11。
- **显示上次的手工测试**：顶部会标明“上次记录”；默认测试方式仍是网格判题。点击测试按钮才会发送新的测试。
- **题目标签已关闭或切换**：打开正确题目的 IDE，重新从目标 C++ 文件打开评测页，必要时更换关联。
- **请求超时或未确认**：先核对网站记录，再决定下一步。界面会显示最后阶段和可获得的具体错误；不要把未确认当作成功。
- **只有手工输出、没有标准答案差异**：确认“手工输入”未勾选。非空 `stdin` 会启用网站手工输入模式。

最终原文到达时间取决于网站评测和连接状态，不保证所有题目都在 1.5 秒内完成。“首次回复”表示首次网站回执耗时，不等于最终评测耗时。

## 数据与协作

| 位置 | 内容 |
| --- | --- |
| `data/grid-tests/` | 每次网站测试的代码快照、输入、编号与反馈。 |
| `data/oj-submissions/` | 正式提交记录；目录名沿用既有实现。 |
| `data/vscode-context/` | 文件与题目关联、对话草稿。 |
| `data/problems/`、`data/hints/`、`data/assistance/` | 题目时间线、提示与交流记录。 |
| `archives/`、`reports/` | 本机完成归档与学习报告。 |

这些个人目录、本机路径配置与凭据均由 `.gitignore` 排除。协作时只提交程序、文档和明确发布的安装包；不要上传个人作业或记录。Chrome 登录由网站处理，工具不导出 Cookie 或密码。

按日期整理需要先预览并确认，仅移动当前项目根目录的 `.c`、`.cc`、`.cpp`、`.cxx`，按本机最后修改日期放入 `按日期整理/YYYY-MM-DD/`。依赖旧路径的编译任务可能需要自行更新。

## AI 模型与判定外观（0.2.9）

- 点击状态栏 **网格·AI**，或执行 **编程网格：选择 AI 模型与推理强度**，先选模型再选强度。取消任一步都不保存本次选择。
- 默认 **GPT-6 Luna / low**。列表提供 Luna、Sol、Astra 和自定义模型 ID；强度有 low、medium、high、xhigh、max，Luna 与自定义模型还可选 none（需模型支持）。
- 提示、交流、保存后的后台报告统一使用这组配置，从下次请求生效；已在生成的回复继续使用原配置。不自动换模型重试。模型和强度可用性取决于当前 Codex 登录账号与服务端。
- 执行 **编程网格：打开插件设置**，或点评测页底部设置按钮，可分别修改 AC、WA、CE、TLE、RE、MLE、PE、OLE 大字头的 **文字、字号、颜色**，已打开的评测页立即更新。
- 文字留空保留网站完整判定名；字号 0 使用原有自适应字号，其他数字按 px（最大 200）；颜色留空保留默认色，或填写 `#e87863` 等十六进制颜色。只改变大字头，网站原文保持原样。
- 配置保存在 VS Code 用户设置，不写入共享项目。AI 配置同步到本机私有 `data/coach-model-settings.json`，工作进程每次请求前读取。独立命令行未有此文件时，可用 `PKU_MODEL`、`PKU_MODEL_EFFORT` 环境变量，最后回退 Luna / low。
- 0.2.9 当时 Chrome 仍为 0.2.7；升级 0.2.11 需按下文重载 Chrome 连接。

用户设置 JSON 示例（也可以直接使用设置界面的输入框）：

```json
{
  "gridCoach.ai.model": "gpt-6-luna",
  "gridCoach.ai.effort": "low",
  "gridCoach.verdicts.WA.text": "Wrong Answer",
  "gridCoach.verdicts.WA.fontSize": 64,
  "gridCoach.verdicts.WA.color": "#e87863"
}
```

本次未进行真实模型测速，不承诺固定额度节省比例。模型 ID 参考 [OpenAI 官方模型目录](https://developers.openai.com/api/docs/models)。


## 题目原文里的计时器（0.2.10）

侧边栏“当前题目信息”的题目原文上方集成 **秒表 / 倒计时**，两者独立保存，可以同时运行，切换标签不会暂停另一项。

- 秒表：开始、暂停、继续、归零。
- 倒计时：输入分钟和秒，点击开始应用时长；可暂停、继续、重置，默认 25 分钟，最多 7 天。修改时长后点击开始，会按新时长重新计时。
- 到时归零并显示提醒；隐藏侧栏后仍由 VS Code 扩展计时。
- 状态存入 VS Code 当前工作区私有存储，不进入项目文件或 Git。重新加载窗口、重新打开同一工作区后按保存时间恢复；电脑休眠和关闭 VS Code 的时间也计入。VS Code 关闭期间不会弹出提醒，重新打开后补发到时提醒。
- 当前是一组工作区计时器，切换题目不会自动归零，不是每道题独立统计用时。不同 VS Code 窗口各自运行；更改系统时钟可能影响时间差。
- 计时器本身不经过浏览器、本机评测后台或 AI；升级 0.2.11 的题目导航需重载 Chrome 连接。

题目列表识别和快速切题的可行性见[调研文档](docs/problem-navigation-research.md)。0.2.11 已加入题单和切题入口，操作方法见下文。


## 题目列表与快速切题（0.2.11）

在题目原文侧栏，计时器下方新增 **本次作业** 区域：

- 连接当前 IDE 后自动读取题单；展开“选择题目”可搜索题名/序号、查看网站顺序和当前题。
- 点击题目，或使用“上一题 / 下一题”，同时切换网页 IDE、题面和对应源码。
- 优先读取网站实际菜单 `ol > li[id^="li_"]`，包含没有 href 的当前题。菜单尚未加载时可在网页展开一次再点“刷新”；另有当前题集 HTML 的只读回退。只识别到一题时明确提示，不假装拿到了完整题单。
- 网页已有目标题 IDE 时复用标签，否则新开；保留原网页编辑器的草稿。
- 已关联的本题源码继续打开；新题在项目的 `编程网格/<题集ID>/<题目ID>.cpp` 创建独立空白文件，已有文件不覆盖。多项目时选择保存位置，没有项目时创建 C++ 未命名文档；未命名源码需自行保存。
- 原文件保留在 VS Code 中，不自动保存、关闭或改写。只有明确关联过的文件会被当作对应题目的已有源码；首次关联可用“编程网格：关联当前 C++ 文件与 Chrome 题目”。
- 文件映射存入当前工作区私有存储。换题不触发 AI、测试、提交，也不重置计时器。
- 切题未完成时拦截新测试/提交；关联失败后可刷新并重选题目，或明确重新关联当前文件。中断状态在重载后仍保留，完成关联后恢复操作。

**此次更新需要同时更新 Chrome 连接与 VS Code：** Chrome 扩展管理页重新加载“编程网格 · VS Code 连接”，回到 IDE 点击连接图标确认 ON；VS Code 运行 `Developer: Reload Window`。两端与本机程序版本均为 0.2.11。

目前按用户提供的真实菜单 HTML 实现并完成语法检查、打包；尚未在登录后的网站做完整切题联调。首次使用请确认题单、目标题名、打开的源码三者对应。
