## 三个按钮

| 按钮 | 行为 |
| --- | --- |
| 测试运行 | 先保存当前完整代码（含未写入源文件的修改）、题面与评测，再用题目样例在临时副本上编译运行。独立结果页对照预期/实际输出，带“收起”和“提交到 OJ”；报告在后台继续。 |
| 提示 | 每次点击都读取并保存当前代码、题面和运行信息，立即更新解题方向与局部改法；相同内容复用，完整解答需另点按钮。 |
| 交流 | 打开提示面板里的对话区。每轮问题与当时完整源码、选中片段和评测证据一同保存，供后续报告参考。 |

三个按钮使用 VS Code 编辑区内的插件标签页，首次在源码旁打开；后续复用该编辑组的位置，打开新功能先关闭上一页，同一时间最多保留一个教练标签页。三个状态栏按钮一直保留。“收起”关闭插件标签页并回到源码。切换前保留未发送草稿；已保存的后台分析与本次提交评测刷新继续进行。不再启动独立浮窗进程。

问答输入框在对话上方。打开提示时交流默认折叠，每次按当前代码更新提示；恢复历史不重复调用模型。代码高亮并附复制按钮；完整解答先给代码，不加注释，使用 `using namespace std;` 和 `cnt+1` 形式的紧凑运算符排版，保留 C++ 必需的空格。

## 读取和保存的边界

- **网站边界**：没有常驻题目脚本，不添加网页按钮、样式或编辑器，不访问网站存储、不清缓存。导航事件只读同步题面；只有用户明确点击“提交到 OJ”才填入官方代码框、选择编译器并向已核对的官方表单发送一次请求。刷新评测只使用 GET，不会重复提交。
- **VS Code 源码只读**：按按钮时读取完整缓冲区，不覆盖、自动保存或格式化源码；不修改 `settings.json`、快捷键、主题、工作区、运行或调试配置。仅增加插件自己的命令、三个状态栏按钮和问答面板。
- **本机文件存储**：源码快照、题面、运行证据、问答与 debug 时间线存在本程序 `data/`，不存 Chrome。定期报告默认放在 `reports/`，可用本机私有的 `native/report-location.json` 指定其他本机文件夹。VS Code 的插件专属目录只可保存所选本机程序位置。标签页通过 VS Code 的消息接口传递界面内容，不使用 `localStorage`、`sessionStorage` 或 Webview `setState` 存储源码和对话，不共用 Google Chrome 配置或网站存储。
- **模型生成**：分析通过已登录的本机 Codex 调用模型，使用相应账户额度，并非离线模型。默认提示、解答和交流使用 `gpt-6.1-sol`、`high`，后台逐次分析使用同模型的 `xhigh`；可在教练标签页的“模型设置”分别调整。交互继续流式显示，完整提示和解答不能保证 3—5 秒内结束。
- **GitHub 只放工具与文档**：没有自动上传作业功能；源码快照、历史、运行信息、报告和最终归档均排除在发布清单之外。

## 安装（Windows 桌面版）

需要 Node.js 22+、Google Chrome、VS Code、`g++` 和已登录的 Codex 可执行程序。

1. 下载或克隆 **openjudge-vscode** 分支到独立文件夹。
2. 在本分支根目录执行 `npm ci --ignore-scripts`。
3. 运行 `.\install-openjudge.ps1`。可显式传入 `-NodePath`、`-CodexPath`、`-CompilerPath`，使用实际可执行文件的绝对路径；Codex 不应是 PowerShell 包装脚本。脚本只注册 `edu.openjudge.cpp_coach`，不会替换旧版 `edu.pku.cpp_coach`。
4. Chrome 打开 `chrome://extensions`，启用开发者模式，加载本分支的 **extension** 文件夹。在 OpenJudge 页点击“OpenJudge · VS Code 连接”图标；角标 `ON` 表示就绪。
5. VS Code 扩展菜单选择“从 VSIX 安装”，安装 [dist/openjudge-cpp-coach-0.5.5.vsix](dist/openjudge-cpp-coach-0.5.5.vsix)。安装包只含 VS Code 界面，需与本机程序和 Chrome 连接配套。
6. 打开可信工作区中的 C++ 文件。Chrome 打开具体题目后，左侧自动显示题面，三个按钮跟随该题；升级后在 Chrome 扩展卡片刷新一次，在 VS Code 重新加载窗口。

完整说明见 [VS Code 适配与限制](vscode-extension/README.md)。源码构建安装包：

```powershell
npm run build:vscode
cd vscode-extension
npx --yes @vscode/vsce package --no-dependencies --skip-license
```

## 题目、代码与 AC

支持 `bailian.openjudge.cn` 和 `noi.openjudge.cn` 的具体题目与提交详情，例如 `/practice/1001/`、`/ch0101/10/` 和同题集的 `/solution/提交编号/`。

浏览器打开或切换题目时，VS Code 左侧自动显示描述、输入、输出和样例，保留网页原文，不自动翻译，不调用模型、不读取源码。存储按“站点＋题集＋题号”区分；复用同一个 `main.cpp`、删掉代码再写另一题也分别保存，不依赖文件名。旧题的窗口不能把新题代码写入旧题；重新点三个按钮会打开当前题目的记录。

提示、解答或交流每次动作重新采集网页评测与当前代码。题面分开保存 **描述、输入、输出、样例输入、样例输出**，保留样例缩进和换行；评测、编译错误另存，不与样例混合。

Chrome 打开对应提交详情后，可在教练中“选择提交详情标签”。只有 **题号相符、提交源码完整可读、与本轮 VS Code 代码一致** 才关联 AC/WA/CE 等结果；匹配的 AC 在本机后台生成完成归档与 README。源码缺失或网页结构无法核对时标“未核对”，不把旧 AC 当修改后代码的结果。

提交详情通常需要自己在 Chrome 登录。连接不处理密码；网站未展示的标准输出、运行输入和隐藏测试记录为缺失，不拿样例冒充实际输出。

## 保存与报告

多题独立保存，同题不同版本按时间排列，diff、运行信息和问答用于复盘修改及 debug。完全相同内容合并展示，保留次数和原顺序；不同运行证据或问题单独记录，保留 A→B→A 的回退。

保存完成即返回，深度分析在后台继续，失败仍保留原始快照。后台逐次分析存入 `data/`；定期总结只保留可直接阅读的自包含 HTML，按北京时间在同一份报告中追加逐题更新；阅读文件夹不放 Markdown、ref 或单独源码，周期状态另存本机私有目录。**定期报告由桌面 Codex 的计划任务生成，VS Code 扩展本身没有定时服务。**

沿用北京时间 **周三 11:30、周五 08:30**。在 Codex 中建立两次计划任务，使用 [定期报告任务说明](docs/periodic-reports.md)，将项目目录替换成自己的安装目录。其他人下载仓库后需自行建立任务，不继承作者账户或日程；本机任务需要电脑开机、桌面应用运行且目录可访问。[官方计划任务说明](https://learn.chatgpt.com/docs/automations?surface=app)

报告只保留每道题单独讨论，不再生成前六个整体总结板块。每题先放完整原题、样例和本人原样源码，再说明修改、debug、问答证据、复杂度及必要参考程序。每次追加标明北京时间，保留已有讨论；相同证据不重复添加。HTML 每题独立默认折叠，可同时展开多个；宽屏题面与源码并列，窄屏上下排列，打印时自动展开并恢复。Markdown、公式与代码均渲染。

| 目录 | 内容 |
| --- | --- |
| `data/` | 完整代码快照、独立运行记录、逐次分析和题目时间线。 |
| `data/assistance/`、`data/hints/` | 提示/交流请求、流式进度、回复及快照关联。 |
| `data/vscode-context/` | 文件题目绑定与对话草稿；不改源文件。 |
| `archives/` | 匹配 AC 后的本机完成归档与 README。 |
| `reports/` | 默认阅读报告目录；可用本机私有配置更改。周期状态另行指定到阅读目录外。 |

这些目录均为本机私有数据，已加入 `.gitignore`。

## 模型设置、版本恢复与自定义测试（0.5.0）

- **切换模型**：打开任一教练标签页，点击右上角“更多”→“模型设置”；或运行命令“OpenJudge：模型与推理强度”。分别选择交互回复和后台逐次分析的模型、推理强度，点击“保存设置”。模型清单通过本机 Codex 的 `model/list` 读取，强度选项遵循清单的实际顺序；不硬编码模型名，不启用清单没有的强度。刷新失败时明确标明上次成功读取的缓存，不静默切换模型。账户权限与服务错误仍可能导致请求失败。[官方接口说明](https://learn.chatgpt.com/docs/app-server#list-models-modellist)
- 设置只写入本项目 `data/preferences/models.json`，不修改 Codex 或 VS Code 全局设置；无需重新加载即可用于新交互请求。已入队的交互保留其冻结配置，后台逐次分析按启动时的设置执行。**Codex 计划任务中的定期总结模型由计划任务单独控制**，不由这里改变。
- 每份新回复保留模型、推理强度和生成时间；相同题面、代码、运行信息与相同配置才复用提示。切换配置时创建独立任务，旧回复保留；“用当前模型重新生成”可以主动绕过复用，仍按新的请求单独记录。旧记录未保存生成配置时标为未知，不把它补记成当前模型。
- **找回版本**：点击右上角“更多”→“历史版本”，或运行“OpenJudge：查看本题历史版本”。按题目列出源码版本、保存时间、保存次数和已有判题状态；连续相同源码合并展示，A→B→A 的回退保留。选择后先校验快照，再高亮显示完整源码与打开历史时当前缓冲区的差异。可以复制或导出为新 `.cpp` 文件；导出拒绝覆盖已存在文件，不回填或覆盖编辑器。
- **当前版本提示**：测试/提示/交流标签页显示题号、文件、文档版本、保存时间与源码指纹。编辑器随后改动时提示“内容对应保存时的版本”，只监听版本号变化，不常驻读取或保存代码。
- **提示排队**：同题尚未开始的旧提示可被更新请求替代，记录为 `superseded`；源码和请求事件仍保留，已开始的回复继续保存。交流、完整解答不被这个合并规则取消。排队、生成、失败和完成分别显示，回复可查看生成配置和排队耗时。
- **自定义测试**：展开测试区域下方“自定义测试与本机限制”，填写输入，可选填写预期输出（勾选后空字符串也是有效预期），设置运行限时和内存，点击“保存代码并运行自定义测试”。没有预期时只显示“已运行”，不判断正确性。始终先保存代码再启动编译；自定义数据和原题样例分别存储，后续提示会读取匹配当前代码的最近本机运行。
- 测试结果提供首个差异的行列及附近内容，显式显示空格、制表符、换行和输出结束。默认仍为 2500 ms、256 MiB、输出 64 KiB，可按题目设置本机运行限制；本地限制与 OJ 机器、编译选项可能不同，本机通过不等于官方 AC。
- 学习进展归入对应题目的讨论，依据真实问答、diff 和评测区分重复卡点、已改善和待验证问题，不把建议视为已采纳，也不单凭 AC 推断已经掌握。

从 0.4.0 升级只需安装本机新版 VSIX 后重新加载 VS Code 窗口；本次 Chrome 连接程序没有变化，无需刷新。安装包与后台应使用同一分支的配套版本。

## 测试与提交结果渲染（0.5.1 起）

- 测试和正式 OJ 判题使用统一的深色卡片；AC、WA、CE、TLE、MLE、RE、OLE、PE、评测中和待确认分别显示状态。正式状态以真实 OJ 返回值为准，本机通过显示“样例通过”或“测试通过”。
- 耗时、内存和退出码/编译语言分成信息格；正式提交编号、题号、提交人、内存、耗时、语言、时间仍完整展示，可独立收起。未知值明确标为未提供或未测量。
- 输入独立显示，预期与实际输出在宽窗并列、窄窗上下排列。每块带行号、字符/行数、末尾换行信息、原文复制和“空白符”开关；开关只影响显示，复制始终保留原文。长输出最多预览前 1200 行，并明确提示，复制仍保留已取得的全部内容。
- 首个输出差异以醒目位置提示，展开可比较附近内容。编译错误与警告分别着色；正式 CE 的编译信息放在提交基本信息之前，运行诊断和输入输出保持分开。
- 提交准备、发送、评测等待显示进度卡片；新提交开始时替换上一份状态，避免误看旧 AC。刷新更新同一份结果，不重复提交。渲染和复制均不调用模型，不改变运行参数、源码或保存记录。
- 安装 0.5.1 后，在 VS Code 执行“Developer: Reload Window / 开发人员: 重新加载窗口”。Chrome 连接、模型设置和后台分析程序无需因为本次界面更新而调整。

## 运行样例与 OJ 提交（0.2.0）

- 每次点状态栏“提示”都会保存点击时完整代码、题面和运行信息，包括已有历史对话或面板已打开时；不必另点快捷保存。历史对话继续保留，恢复历史本身不重复调用提示模型。
- **运行样例**：按题目例子输入运行当前代码，在插件里分栏显示预期/实际输出、耗时、源码哈希及编译错误。空白差异单独标记；样例一致不等于 OJ AC。编译限时 8 秒、运行限时 2.5 秒、合计输出限制 64 KiB。
- **提交到 OJ**：读取已登录 Chrome 中本题官方表单及实际 C++ 编译器选项；首次选择编译器，再点击发送当前完整代码。源码快照先写本机；每个点击事件最多发送一次。
- **刷新本次结果**：只查询该次提交，保留提交编号和当时的源码。即使文件已改动，旧提交结果也不会覆盖新代码。正在评测时可自动查询最多 30 次；无法唯一确定编号时停止猜测，可在 Chrome 打开这次提交详情后再刷新。
- 正常使用不碰网站 localStorage、sessionStorage、IndexedDB，也不改网站函数。只有明确提交所需的代码框/编译器字段被赋值，不执行网站的自定义提交脚本。
- 运行与提交记录分别存放 `data/sample-runs/`、`data/oj-submissions/`，一并纳入本机学习报告。样例执行与提交网络耗时独立于模型响应速度。
- 真实登录页需通过表单核对；接口或字段无法识别时会停止并说明，不尝试其他写入地址，不自动重试不确定的提交。开发只用自拟代码和模拟服务验证，不替用户发送测试作业。

## 状态栏测试运行（0.2.2）

右下角保留三个按钮：测试运行、提示、交流。测试运行先保存代码，再测试题目样例；即使缺少样例、编译失败或运行超时，已经确认保存的代码仍保留。结果显示在插件自己的面板，不覆盖源文件、不调用网站测试按钮。

提示面板中的运行样例、提交到 OJ、给出解答等按钮保持原样。原快捷保存命令保留为兼容入口，状态栏不再显示该按钮。

## VS Code 内置题库与提交体验（0.3.0）

- 左侧“经典题库与题面”内置百练 237 题、NOI 100 题；支持搜索题号/题名/知识点、按平台和难度筛选，以及上一题/下一题。前后切换遵循当前筛选结果的题单顺序。
- 打开方式：左侧 OpenJudge 图标，或命令面板运行“OpenJudge：打开经典题库（337 题）”。选择题目即可打开；不需要复制网址。Chrome 连接扩展须已连接。
- 切题只导航 Chrome 中的题目标签并读取原文；已有提交表单不会被题库导航覆盖，VS Code 源码和未保存修改保持原样，不触发保存或模型调用。不同题目仍按站点、题集和题号独立保存。
- 提示中的交流入口放在最上方；点击“提交到 OJ”立即把本次提交状态移到面板顶部并滚动到该处，其他提示按钮保留。
- 从 VS Code 提交后，只有题号、完整源码匹配且真实评测为 AC，才在本机保存结果后关闭本次对应的官方提交页。题目页保留；若提交页已改写代码、已有更新提交或换成其他页面，则保留它。重复刷新不会重复提交。
- 题库为 2026-10-20 核对的快照，NOI 已排除 1.x。百练通过率按目录人数比，NOI 非 1.x 按统计页 AC/总提交次数；90% 及以上均排除。难度改按通过率快照划分，算法范围上限仍保留。
- 升级需刷新 Chrome 中“OpenJudge · VS Code 连接”，再重新加载 VS Code 窗口。浏览器权限没有增加，不清缓存、不改站点函数或 VS Code 设置。

## 独立测试窗口（0.3.1）

- 点右下角“测试运行”，先保存本轮代码，再显示样例输入、预期输出、实际输出及编译信息。窗口右上角新增“收起”和“提交到 OJ”。“收起”回到源码，已保存的代码和测试记录保留；测试未完成时收起也不会取消保存和测试。
- 在测试窗口点“提交到 OJ”，复用提示窗口的官方提交流程：首次核对 C++ 编译器，再点一次发送。提交读取点击时的最新完整代码，包括未写入文件的修改；不会拿旧样例测试的源码替代新代码。提交状态立即置顶，支持刷新本次结果；刷新不会重复发送。
- 真实 AC 仍须题号和完整源码匹配；先保存本机记录，再关闭这次对应的 Chrome 提交页，保留题目页。提示中的交流入口保持在上方，其他按钮保持原有功能。
- 从 0.3.0 升级本版只需安装新版 VSIX 后重新加载 VS Code 窗口，Chrome 连接无需刷新。本次未增加网站权限或更改网站脚本、存储、源码与 VS Code 设置。

## 单个测试窗口与提交详情（0.3.2）

- **最多一个测试运行窗口**：重复点击会复用当前窗口；更换题目或源码文件也复用它。每次点击的代码仍独立保存、测试，先前任务可以继续写入自己的本机记录。旧测试结果和旧页面发出的操作不会覆盖新窗口内容或把提交发到新题目。
- **三个状态栏按钮固定保留**：打开测试运行、提示、交流或题库，按钮都不隐藏。未选中 C++ 源码时点击会说明需要打开代码，不自动读取其他文件。
- **提示默认折叠交流区**：即使上次展开了交流，再次打开提示也会折叠；点击“交流”明确展开。历史问答和未发送草稿保留。对话按新到旧排列，新问题与回复一起放在旧内容上方。
- **OJ 提交基本信息**：提示和独立测试窗口的评测区均显示提交编号、题号、提交人、内存、耗时、编译语言、提交时间。数据来自这次官方提交详情，保留网站单位和时间原文；缺失或冲突项显示“未提供”，不会使用本机样例耗时填充。重新查询会更新同一张信息表，不重复提交；原始详情随提交记录保存在本机。
- 安装 0.3.2 后重新加载 VS Code 窗口，并在 Chrome 扩展管理中刷新一次“OpenJudge · VS Code 连接”（2.2.1），启用新字段读取。权限不变，不清缓存、不改网站函数或 VS Code 设置。
