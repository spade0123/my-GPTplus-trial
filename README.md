# OpenJudge + VS Code C++ 学习教练

Chrome 打开 **百练 / NOI OpenJudge**，VS Code 写 C++，通过右下角状态栏的 **测试运行、提示、交流** 三个按钮记录和复盘。

这是独立适配版：[openjudge-vscode 分支](https://github.com/spade0123/my-GPTplus-trial/tree/openjudge-vscode)。[原北大编程网格版本](https://github.com/spade0123/my-GPTplus-trial/tree/mcp)继续保留，不需要替换或卸载。

## 三个按钮

| 按钮 | 行为 |
| --- | --- |
| 测试运行 | 先保存当前完整代码（含未写入源文件的修改）、题面与评测，再用题目样例在临时副本上编译运行。独立结果页对照预期/实际输出；报告在后台继续。 |
| 提示 | 结合本轮代码、题意及可见评测给解题方向和局部改法；恢复上次提示，可主动重新生成；完整解答需另点按钮。 |
| 交流 | 打开提示面板里的对话区。每轮问题与当时完整源码、选中片段和评测证据一同保存，供后续报告参考。 |

问答使用插件自己的编辑器面板，输入框在对话上方，带“收起”。恢复历史不重复调用模型。代码高亮并附复制按钮；完整解答先给代码，不加注释，使用 `using namespace std;` 和 `cnt+1` 形式的紧凑运算符排版，保留 C++ 必需的空格。

## 读取和保存的边界

- **网站边界**：没有常驻题目脚本，不添加网页按钮、样式或编辑器，不访问网站存储、不清缓存。导航事件只读同步题面；只有用户明确点击“提交到 OJ”才填入官方代码框、选择编译器并向已核对的官方表单发送一次请求。刷新评测只使用 GET，不会重复提交。
- **VS Code 源码只读**：按按钮时读取完整缓冲区，不覆盖、自动保存或格式化源码；不修改 `settings.json`、快捷键、主题、工作区、运行或调试配置。仅增加插件自己的命令、三个状态栏按钮和问答面板。
- **本机文件存储**：源码快照、题面、运行证据、问答、debug 时间线与报告存在本程序目录，不存 Chrome。VS Code 的插件专属目录只可保存所选本机程序位置；源码和对话仍写入本机程序的 `data/`。
- **模型生成**：分析通过已登录的本机 Codex 调用模型，使用相应账户额度，并非离线模型。深度报告默认 `gpt-6.1-sol`、`xhigh`；交互沿用流式快速回复。完整提示和解答不能保证 3—5 秒内结束。
- **GitHub 只放工具与文档**：没有自动上传作业功能；源码快照、历史、运行信息、报告和最终归档均排除在发布清单之外。

## 安装（Windows 桌面版）

需要 Node.js 22+、Google Chrome、VS Code、`g++` 和已登录的 Codex 可执行程序。

1. 下载或克隆 **openjudge-vscode** 分支到独立文件夹。
2. 在本分支根目录执行 `npm ci --ignore-scripts`。
3. 运行 `.\install-openjudge.ps1`。可显式传入 `-NodePath`、`-CodexPath`、`-CompilerPath`，使用实际可执行文件的绝对路径；Codex 不应是 PowerShell 包装脚本。脚本只注册 `edu.openjudge.cpp_coach`，不会替换旧版 `edu.pku.cpp_coach`。
4. Chrome 打开 `chrome://extensions`，启用开发者模式，加载本分支的 **extension** 文件夹。在 OpenJudge 页点击“OpenJudge · VS Code 连接”图标；角标 `ON` 表示就绪。
5. VS Code 扩展菜单选择“从 VSIX 安装”，安装 [dist/openjudge-cpp-coach-0.3.0.vsix](dist/openjudge-cpp-coach-0.3.0.vsix)。安装包只含 VS Code 界面，需与本机程序和 Chrome 连接配套。
6. 打开可信工作区中的 C++ 文件。Chrome 打开具体题目后，左侧自动显示题面，三个按钮跟随该题；升级后在 Chrome 扩展卡片刷新一次，在 VS Code 重新加载窗口。

完整说明见 [VS Code 适配与限制](vscode-extension/README.md)。源码构建安装包：

```powershell
npm run build:vscode
cd vscode-extension
npx --yes @vscode/vsce package --no-dependencies --skip-license
```

## 题目、代码与 AC

支持 `bailian.openjudge.cn` 和 `noi.openjudge.cn` 的具体题目与提交详情，例如 `/practice/1001/`、`/ch0101/10/` 和同题集的 `/solution/提交编号/`。

浏览器打开或切换题目时，VS Code 左侧自动显示描述、输入、输出和样例，保留网页原文，不自动翻译，不调用模型、不读取源码。存储按“站点＋题集＋题号”区分；复用同一个 `main.cpp`、删掉代码再写另一题也分别保存，不依赖文件名。旧题的窗口不能把新题代码写入旧题；重新点三个按钮会打开当前题目的记录。

提示、解答或交流每次动作重新采集网页评测与当前代码。题面分开保存 **描述、输入、输出、样例输入、样例输出**，保留样例缩进和换行；评测、编译错误另存，不与样例混合。

Chrome 打开对应提交详情后，可在教练中“选择提交详情标签”。只有 **题号相符、提交源码完整可读、与本轮 VS Code 代码一致** 才关联 AC/WA/CE 等结果；匹配的 AC 在本机后台生成完成归档与 README。源码缺失或网页结构无法核对时标“未核对”，不把旧 AC 当修改后代码的结果。

提交详情通常需要自己在 Chrome 登录。连接不处理密码；网站未展示的标准输出、运行输入和隐藏测试记录为缺失，不拿样例冒充实际输出。

## 保存与报告

多题独立保存，同题不同版本按时间排列，diff、运行信息和问答用于复盘修改及 debug。完全相同内容合并展示，保留次数和原顺序；不同运行证据或问题单独记录，保留 A→B→A 的回退。

保存完成即返回，深度分析在后台继续，失败仍保留原始快照。后台逐次分析存入 `data/`；定期总结输出 Markdown 与已渲染 HTML 到 `reports/`，维护 `index.html`。**定期报告由桌面 Codex 的计划任务生成，VS Code 扩展本身没有定时服务。**

沿用北京时间 **周三 11:30、周五 08:30**。在 Codex 中建立两次计划任务，使用 [定期报告任务说明](docs/periodic-reports.md)，将项目目录替换成自己的安装目录。其他人下载仓库后需自行建立任务，不继承作者账户或日程；本机任务需要电脑开机、桌面应用运行且目录可访问。[官方计划任务说明](https://learn.chatgpt.com/docs/automations?surface=app)

报告前六部分整体归纳，具体题目统一放末尾：

1. 代码中普遍的冗余部分。
2. 输入手段的优化与拓展。
3. 可替代原始实现的函数与关键字。
4. 更简洁的解法与参考程序。
5. 头文件、函数与关键字分类拓展。
6. 时间与空间复杂度及优化方向。

末尾逐题附录先放完整原题、样例和本人代码，再说明改动、问答证据、问题及参考程序。HTML 每题默认折叠，仅显示标题，可同时展开多个，打印时展开；Markdown、公式和代码渲染沿用原版。

| 目录 | 内容 |
| --- | --- |
| `data/` | 完整代码快照、独立运行记录、逐次分析和题目时间线。 |
| `data/assistance/`、`data/hints/` | 提示/交流请求、流式进度、回复及快照关联。 |
| `data/vscode-context/` | 文件题目绑定与对话草稿；不改源文件。 |
| `archives/` | 匹配 AC 后的本机完成归档与 README。 |
| `reports/` | 定期学习报告、索引和周期状态。 |

这些目录均为本机私有数据，已加入 `.gitignore`。

## 兼容与验证

首版适配 Windows 桌面 VS Code + Chrome。“运行样例”仅在明确点击时，用临时副本编译并运行，限制时间和输出，不改源文件或 VS Code 的运行/调试配置。“提交到 OJ”会将本次代码发给 OJ，不会上传 GitHub。不自动读取其他扩展的 Output、Debug Console 或终端滚动历史；缺失的运行信息不编造。VS Code 网页版和 SSH/WSL/容器远程源码未适配。

已核对公开题目的实际 `dt/dd` 结构，并只读核对百练 1004 已登录提交页的语言单选项、`sourceEncode=base64` 和官方 `/api/solution/submitv2/` 地址。源码按 UTF-8 Base64 编码，不调用网站提交脚本。真实评测结果仍需通过用户主动提交核对；开发测试未发送个人作业。

已通过 145 个测试，并在隔离 Chrome/VS Code 配置中用虚构题目验证原生连接、三按钮、未保存源码、提示/交流/解答、语法渲染、磁盘草稿、匹配 AC 与收起。检查网页 DOM/存储零修改、源码文件保持原样。测试不使用个人作业，不消耗真实模型额度。

运行 `npm test`；原生连接测试需先运行安装脚本。技术资料：[Webview](https://code.visualstudio.com/api/extension-guides/webview)、[状态栏](https://code.visualstudio.com/api/ux-guidelines/status-bar)、[终端读取边界](https://code.visualstudio.com/api/references/vscode-api#TerminalShellExecution)。

## 运行样例与 OJ 提交（0.2.0）

- 每次点状态栏“提示”都会保存点击时完整代码、题面和运行信息，包括已有历史对话或面板已打开时；不必另点快捷保存。历史对话继续保留，恢复历史本身不重复调用提示模型。
- **运行样例**：按题目例子输入运行当前代码，在插件里分栏显示预期/实际输出、耗时、源码哈希及编译错误。空白差异单独标记；样例一致不等于 OJ AC。编译限时 8 秒、运行限时 2.5 秒、合计输出限制 64 KiB。
- **提交到 OJ**：读取已登录 Chrome 中本题官方表单及实际 C++ 编译器选项；首次选择编译器，再点击发送当前完整代码。源码快照先写本机；每个点击事件最多发送一次。
- **刷新本次结果**：只查询该次提交，保留提交编号和当时的源码。即使文件已改动，旧提交结果也不会覆盖新代码。正在评测时可自动查询最多 30 次；无法唯一确定编号时停止猜测，可在 Chrome 打开这次提交详情后再刷新。
- 正常使用不碰网站 localStorage、sessionStorage、IndexedDB，也不改网站函数。只有明确提交所需的代码框/编译器字段被赋值，不执行网站的自定义提交脚本。
- 运行与提交记录分别存放 `data/sample-runs/`、`data/oj-submissions/`，一并纳入本机学习报告。样例执行与提交网络耗时独立于模型响应速度。
- 真实登录页需通过表单核对；接口或字段无法识别时会停止并说明，不尝试其他写入地址，不自动重试不确定的提交。开发只用自拟代码和模拟服务验证，不替用户发送测试作业。

## 状态栏测试运行（0.2.2）

右下角保留三个按钮：测试运行、提示、交流。测试运行先保存代码，再测试题目样例；即使缺少样例、编译失败或运行超时，已经确认保存的代码仍保留。结果显示在插件自己的面板，不覆盖源文件、不调用网站测试按钮。

提示面板中的运行样例、提交到 OJ、给出解答等按钮保持原样。原快捷保存命令保留为兼容入口，状态栏不再显示该按钮。

## VS Code 内置题库与提交体验（0.3.0）

- 左侧“经典题库与题面”内置百练 237 题、NOI 100 题；支持搜索题号/题名/知识点、按平台和难度筛选，以及上一题/下一题。前后切换遵循当前筛选结果的题单顺序。
- 打开方式：左侧 OpenJudge 图标，或命令面板运行“OpenJudge：打开经典题库（337 题）”。选择题目即可打开；不需要复制网址。Chrome 连接扩展须已连接。
- 切题只导航 Chrome 中的题目标签并读取原文；已有提交表单不会被题库导航覆盖，VS Code 源码和未保存修改保持原样，不触发保存或模型调用。不同题目仍按站点、题集和题号独立保存。
- 提示中的交流入口放在最上方；点击“提交到 OJ”立即把本次提交状态移到面板顶部并滚动到该处，其他提示按钮保留。
- 从 VS Code 提交后，只有题号、完整源码匹配且真实评测为 AC，才在本机保存结果后关闭本次对应的官方提交页。题目页保留；若提交页已改写代码、已有更新提交或换成其他页面，则保留它。重复刷新不会重复提交。
- 题库为 2026-10-20 核对的快照，NOI 已排除 1.x。百练通过率按目录人数比，NOI 非 1.x 按统计页 AC/总提交次数；90% 及以上均排除。难度为学习用估计。
- 升级需刷新 Chrome 中“OpenJudge · VS Code 连接”，再重新加载 VS Code 窗口。浏览器权限没有增加，不清缓存、不改站点函数或 VS Code 设置。
