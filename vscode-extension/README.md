# 北大编程网格 · C++ 学习教练 · VS Code

这版面向 `https://programming.pku.edu.cn` 的题目 IDE，与仓库原有的 OpenJudge 插件分开安装。状态栏的 **网格·评测** 打开网站测试、正式提交与网站原文页面；**网格·提示** 和 **网格·交流** 在另一个 AI 页面。

## 安装

1. 安装 Node.js 22+、G++、已登录的 Codex，以及桌面版 VS Code 和 Chrome。在本项目根目录运行 `npm ci --ignore-scripts`。
2. 在本项目根目录运行 `powershell -ExecutionPolicy Bypass -File .\install-grid.ps1`。需要时可指定 `-NodePath`、`-CodexPath`、`-CompilerPath`。它注册独立的 `edu.pku.grid_vscode_coach` 本机连接，不会覆盖 OpenJudge 连接。
3. 在 Chrome 扩展管理页打开开发者模式，选择“加载已解压的扩展程序”，选择本项目的 `extension/` 目录；如果已加载，更新源码后点“重新加载”。在 Chrome 自己登录编程网格并打开具体题目的 `/ide.do` 页面，点击“编程网格 · VS Code 连接”图标。
4. 在 VS Code 里通过“从 VSIX 安装”选择 `dist/pku-grid-cpp-coach-0.2.3.vsix`，打开 C++ 文件。如果安装后没有看到“网格·保存 / 网格·评测 / 网格·提示 / 网格·交流”，重新加载 VS Code 窗口。旧 OpenJudge 插件是另一项安装，不影响这一项的名称。

## 它怎样工作

```text
编程网格题目 IDE ──Chrome 连接扩展──本机连接程序──VS Code 插件
       │                                      │               │
       └─题面、评测状态                       本机记录      当前编辑器代码
                                              │               │
                                              └──提示/交流─────┘
```

Chrome 负责读取题目网页；VS Code 负责读取当前编辑器内的完整代码，包括尚未保存到文件的改动。本机程序负责把同一题的题面、代码快照和交流记录放在一起。浏览器登录由网站自己处理，插件不收集密码。

**网站测试执行**从 VS Code 读取点击时的完整代码和面板中的测试输入，经 Chrome 已登录会话调用网站自己的测试执行。输入框首次填入题目的例子输入，可以自行修改，空输入也会作为测试输入发送。网站先返回的接口原文立即显示在页面顶部；随后按本次编号查询提交详情页，把大字 AC/WA/CE/TLE 等状态和“提示信息”原文显示在顶部。测试请求在网站脚本里是带 `stdin` 的 `submit.do`；正式提交是同一个地址但不带 `stdin`。

**正式提交到编程网格**是独立按钮。点击一次后，插件核对题目页面和 C++ 编译器，保存当前代码快照并调用网站自己的正式提交接口。测试与提交各有自己的编号和结果区域；刷新只查询对应编号，不重复发送。页面再次打开时会恢复该题最近一次测试和提交记录。网站回复和本机报告保存分开进行，报告处理不会挡住原文显示。返回状态不确定时不会自动重试。

网站返回的 AC/WA 等结果只与相同题号、相同代码关联。网站未提供的隐藏测试输入和标准输出不会被填入记录。当前适配以 C++、Windows 桌面版 VS Code 和 Chrome 为目标。

## 按日期整理项目源码

打开项目文件夹后，点击状态栏的“按日期整理”，或在命令面板运行“编程网格：按日期整理项目源码”。插件预览将移动的文件，确认后只把**项目根目录**的 `.c`、`.cc`、`.cpp`、`.cxx` 文件按本机最后修改日期放进 `按日期整理/YYYY-MM-DD/`。已有子文件夹、配置文件和头文件不会移动；同名文件会自动加编号。VS Code 使用工作区文件操作执行移动，整理后可在资源管理器和 Git 变更列表核对。如编译任务写死了旧路径，需要更新任务路径。

## 当前验证边界

编程网格公开的 [`ide-submit-15.js`](https://programming.pku.edu.cn/static/ide-submit-15.js) 确认了 `stdin` 区分测试与提交、使用 `submit.do` 发送以及按编号查询 `/solution/{id}/status.do` 的流程。提交详情页按 `/solution/{id}/` 读取。开发时没有使用用户账号进行真实测试或提交；首次使用请在浏览器确认题目开放、账号已登录，并核对网站记录与 VS Code 显示是否一致。页面会立即显示“正在等待网站回复”，实际评测原文到达时间仍取决于网站和 Chrome 连接。
