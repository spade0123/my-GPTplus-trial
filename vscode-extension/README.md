# 北大编程网格 · C++ 学习教练 · VS Code

这版面向 `https://programming.pku.edu.cn` 的题目 IDE，与仓库原有的 OpenJudge 插件分开安装。状态栏的 **网格·评测** 打开网站测试、正式提交与网站原文页面；**网格·提示** 和 **网格·交流** 在另一个 AI 页面。

## 安装

1. 安装 Node.js 22+、G++、已登录的 Codex，以及桌面版 VS Code 和 Chrome。在本项目根目录运行 `npm ci --ignore-scripts`。
2. 在本项目根目录运行 `powershell -ExecutionPolicy Bypass -File .\install-grid.ps1`。需要时可指定 `-NodePath`、`-CodexPath`、`-CompilerPath`。它注册独立的 `edu.pku.grid_vscode_coach` 本机连接，不会覆盖 OpenJudge 连接。
3. 在 Chrome 扩展管理页打开开发者模式，选择“加载已解压的扩展程序”，选择本项目的 `extension/` 目录；如果已加载，更新源码后点“重新加载”。在 Chrome 自己登录编程网格并打开具体题目的 `/ide.do` 页面，点击“编程网格 · VS Code 连接”图标。
4. 在 VS Code 里通过“从 VSIX 安装”选择 `dist/pku-grid-cpp-coach-0.2.13.vsix`，重新加载 VS Code 窗口。状态栏固定显示“网格·保存 / 网格·评测 / 网格·提示 / 网格·交流”；点击时核对当前 C++ 文件。重载后焦点停在面板时，若只有一个可见的 C++ 编辑器，会恢复该源码来源；多个来源时请先选中目标文件。旧 OpenJudge 插件是另一项安装，不影响这一项的名称。

## 它怎样工作

```text
编程网格题目 IDE ──Chrome 连接扩展──本机连接程序──VS Code 插件
       │                                      │               │
       └─题面、评测状态                       本机记录      当前编辑器代码
                                              │               │
                                              └──提示/交流─────┘
```

Chrome 负责读取题目网页；VS Code 负责读取当前编辑器内的完整代码，包括尚未保存到文件的改动。本机程序负责把同一题的题面、代码快照和交流记录放在一起。浏览器登录由网站自己处理，插件不收集密码。

**测试代码 · 网格判题**从 VS Code 读取点击时的完整代码，经 Chrome 已登录会话调用网站自己的测试执行。默认发送空的 `stdin` 字段，与网页“测试代码”的请求一致，让网格返回测试判定、标准输出差异和平台提示。可选的“手工输入”区域默认关闭；只有勾选启用后，才会发送输入框中的内容，让用户自行核对输出。自动填入的样例不会改变默认判题模式。正式提交使用同一 `submit.do` 地址，并省略 `stdin` 字段。

页面顶部显示网站原文和大字完整判定名称，例如 Accepted、Wrong Answer、Compile Error、Time Out；保留对应颜色。测试接口外层为 `Testing` 时，仅根据网站原文 `Result:` 行的实际判定显示结果；“Complete! Please check the output by yourself”表示手工测试结束，不作为 Accepted。网站接口的 `hint` 原文优先保留，详情页内容用于补充。

“手工输入”入口紧跟测试与提交按钮，默认关闭。页面仅显示判定、网站原文和必要提示，原始接口 JSON 留在本机记录中。重新打开只恢复上次记录，不自动查询；当前操作拿到结束判定和原文后停止自动查询。旧版误标 pending 的已完成手工测试会在本机纠正状态，不向网站重复发送代码。

**正式提交到编程网格**是独立按钮。点击一次后，插件核对题目页面和 C++ 编译器，保存当前代码快照并调用网站自己的正式提交接口。测试与提交各有自己的编号和结果区域；刷新只查询对应编号，不重复发送。页面再次打开时会恢复该题最近一次测试和提交记录。网站回复和本机报告保存分开进行，报告处理不会挡住原文显示。返回状态不确定时不会自动重试。

网站返回的 AC/WA 等结果只与相同题号、相同代码关联。网站未提供的隐藏测试输入和标准输出不会被填入记录。当前适配以 C++、Windows 桌面版 VS Code 和 Chrome 为目标。

等待时顶部会显示请求经过的阶段，超时信息也会带上最后阶段。提交详情页一旦返回即可显示，不等待较慢的状态接口；详情仍为 pending 时会继续查询。网站拒绝请求时保留接口原文，刷新失败时保留此前收到的评测原文。更新后需要重新加载 Chrome 连接扩展及 VS Code 窗口，让两端和本机连接程序都运行新版。

网页内执行的请求会把异常作为普通数据返回，避免 Chrome 丢失失败 Promise 的返回值后只显示“未确认网站返回”。执行编号按网站返回的安全字符串保存，支持数字、字母、连字符和下划线；非 JSON 回复也会保留原文。

## 按日期整理项目源码

打开项目文件夹后，点击状态栏的“按日期整理”，或在命令面板运行“编程网格：按日期整理项目源码”。插件预览将移动的文件，确认后只把**项目根目录**的 `.c`、`.cc`、`.cpp`、`.cxx` 文件按本机最后修改日期放进 `按日期整理/YYYY-MM-DD/`。已有子文件夹、配置文件和头文件不会移动；同名文件会自动加编号。VS Code 使用工作区文件操作执行移动，整理后可在资源管理器和 Git 变更列表核对。如编译任务写死了旧路径，需要更新任务路径。

## AI 模型与判定外观（0.2.9）

- 点击状态栏 **网格·AI**，或执行 **编程网格：选择 AI 模型与推理强度**，先选模型再选强度。取消任一步都不保存本次选择。
- 默认 **GPT-6 Luna / low**。列表提供 Luna、Sol、Astra 和自定义模型 ID；强度有 low、medium、high、xhigh、max，Luna 与自定义模型还可选 none（需模型支持）。
- 提示、交流、保存后的后台报告统一使用这组配置，从下次请求生效；已在生成的回复继续使用原配置。不自动换模型重试。模型和强度可用性取决于当前 Codex 登录账号与服务端。
- 执行 **编程网格：打开插件设置**，或点评测页底部设置按钮，可分别修改 AC、WA、CE、TLE、RE、MLE、PE、OLE 大字头的 **文字、字号、颜色**，已打开的评测页立即更新。
- 文字留空保留网站完整判定名；字号 0 使用原有自适应字号，其他数字按 px（最大 200）；颜色留空保留默认色，或填写 `#e87863` 等十六进制颜色。只改变大字头，网站原文保持原样。
- 配置保存在 VS Code 用户设置，不写入共享项目。AI 配置同步到本机私有 `data/coach-model-settings.json`，工作进程每次请求前读取。独立命令行未有此文件时，可用 `PKU_MODEL`、`PKU_MODEL_EFFORT` 环境变量，最后回退 Luna / low。
- 0.2.9 当时 Chrome 仍为 0.2.7；升级 0.2.11 需按下文重载 Chrome 连接。

用户设置 JSON 示例（也可以直接使用设置界面的输入框）：

```json
{
  "gridCoach.ai.model": "gpt-6-luna",
  "gridCoach.ai.effort": "low",
  "gridCoach.verdicts.WA.text": "Wrong Answer",
  "gridCoach.verdicts.WA.fontSize": 64,
  "gridCoach.verdicts.WA.color": "#e87863"
}
```

本次未进行真实模型测速，不承诺固定额度节省比例。模型 ID 参考 [OpenAI 官方模型目录](https://developers.openai.com/api/docs/models)。


## 题目原文里的计时器（0.2.10）

侧边栏“当前题目信息”的题目原文上方集成 **秒表 / 倒计时**，两者独立保存，可以同时运行，切换标签不会暂停另一项。

- 秒表：开始、暂停、继续、归零。
- 倒计时：输入分钟和秒，点击开始应用时长；可暂停、继续、重置，默认 25 分钟，最多 7 天。修改时长后点击开始，会按新时长重新计时。
- 到时归零并显示提醒；隐藏侧栏后仍由 VS Code 扩展计时。
- 状态存入 VS Code 当前工作区私有存储，不进入项目文件或 Git。重新加载窗口、重新打开同一工作区后按保存时间恢复；电脑休眠和关闭 VS Code 的时间也计入。VS Code 关闭期间不会弹出提醒，重新打开后补发到时提醒。
- 当前是一组工作区计时器，切换题目不会自动归零，不是每道题独立统计用时。不同 VS Code 窗口各自运行；更改系统时钟可能影响时间差。
- 计时器本身不经过浏览器、本机评测后台或 AI；升级 0.2.11 的题目导航需重载 Chrome 连接。

题目列表识别和快速切题的可行性见[调研文档](../docs/problem-navigation-research.md)。0.2.11 已加入题单和切题入口，操作方法见下文。


## 题目列表与快速切题（0.2.11）

在题目原文侧栏，计时器下方新增 **本次作业** 区域：

- 连接当前 IDE 后自动读取题单；展开“选择题目”可搜索题名/序号、查看网站顺序和当前题。
- 点击题目，或使用“上一题 / 下一题”，同时切换网页 IDE、题面和对应源码。
- 优先读取网站实际菜单 `ol > li[id^="li_"]`，包含没有 href 的当前题。菜单尚未加载时可在网页展开一次再点“刷新”；另有当前题集 HTML 的只读回退。只识别到一题时明确提示，不假装拿到了完整题单。
- 网页已有目标题 IDE 时复用标签，否则新开；保留原网页编辑器的草稿。
- 已关联的本题源码继续打开；新题在项目的 `编程网格/<题集ID>/<题目ID>.cpp` 创建独立空白文件，已有文件不覆盖。多项目时选择保存位置，没有项目时创建 C++ 未命名文档；未命名源码需自行保存。
- 原文件保留在 VS Code 中，不自动保存、关闭或改写。只有明确关联过的文件会被当作对应题目的已有源码；首次关联可用“编程网格：关联当前 C++ 文件与 Chrome 题目”。
- 文件映射存入当前工作区私有存储。换题不触发 AI、测试、提交，也不重置计时器。
- 切题未完成时拦截新测试/提交；关联失败后可刷新并重选题目，或明确重新关联当前文件。中断状态在重载后仍保留，完成关联后恢复操作。

**此次更新需要同时更新 Chrome 连接与 VS Code：** Chrome 扩展管理页重新加载“编程网格 · VS Code 连接”，回到 IDE 点击连接图标确认 ON；VS Code 运行 `Developer: Reload Window`。两端与本机程序版本均为 0.2.11。

目前按用户提供的真实菜单 HTML 实现并完成语法检查、打包；尚未在登录后的网站做完整切题联调。首次使用请确认题单、目标题名、打开的源码三者对应。


## 题集关闭倒计时（0.2.12）

“本次作业”区域显示 **x 天 x 小时 x 分钟后题集关闭**；不到一分钟时显示“不到 1 分钟后题集关闭”，到点后显示“已到题集关闭时间”。悬停可查看完整截止时刻（北京时间），剩余不足一天时突出显示。

- 优先从网页自己的 `problemlist.closeTime` 一次性读取精确截止时间；该值由网站将 `problemlist.assignment.closeTime` 转换成日期而来。
- 优先使用网站已转换的日期/时间戳，必要时读原始时间字符串；无时区的完整网站日期按北京时间解释。
- 网站未暴露此变量时，尝试明确命名的关闭时间字段，并可通过课程链接按当前题集 ID 查找 `.closeTime`；不拿其他题集时间代替。
- 获取后由 VS Code 本地时钟计算，每秒只重画文字，**没有定时网络同步**。同一题集切题继续共用同一截止时刻，按题集保存本机缓存。
- 点击题单“刷新”会重新读取网页当前配置；老师改期后应先刷新网页，再刷新题单。
- 没有精确截止时间时明确显示缺失，不用“6 天”等取整文字推算；本机时间不准会影响剩余时间，网站是否允许提交以网站为准。

升级本次 0.2.12 需重新加载 Chrome 连接扩展，并在 VS Code 执行 `Developer: Reload Window`。实现依据用户提供的网站代码和 DOM；已做语法检查与打包，尚未在登录后的实际网页完整联调。


## 题单进度、轻量计时与源码模板（0.2.13）

### 题干优先的布局

题干、输入输出和样例先显示，“本次作业”与题单移到题干下方。顶部计时器缩成一行，滚动阅读时仍固定在视野中；“⋯”中放置范围选择、倒计时设置和显示重置。

### 最近评测圆点与累计用时

题名左侧圆点显示插件本机记录的最近一次情况：绿色 AC，红色 WA/RE，橙色 CE/PE/OLE，紫色 TLE/MLE，黄色等待回复，蓝色手工测试完成，灰色无记录/未确认。悬停查看完整状态、测试还是正式提交，以及北京时间；网站上独立进行、未被插件记录的历史暂不自动同步，灰色不等于从未做过。

按尝试发起时间决定“最近一次”，旧提交晚到的刷新不会覆盖新尝试。评测记录更新通过本机文件通知传到侧栏，不逐题轮询网站。

题名右侧显示累计耗时。本题计时开始后累计；切题暂停上一题，回到题目继续使用已保存的值。秒表或倒计时任一运行都会计入，两者同时运行不重复计算。重置显示不会清除累计耗时。

### 整套计时

题单中的“整套计时”或悬浮条“⋯ → 计时范围 → 整套题单”切换查看独立总计时。它复用秒表/倒计时，按题集保存；开始总计时会启动当前题计时，切题后累计到新题；暂停总计时会暂停本题计时。没有考试模式开关，不自动隐藏或打开 AI 页面。

所有计时保存在 VS Code 工作区私有存储，不写进项目。计时不是编辑器击键活动统计，运行期间离开电脑/关闭 VS Code 的时间也可能计入；需要休息时请暂停。换到另一题集不自动暂停原题集的总计时。

### 简短英文源码与模板

新题文件使用英文关键词和短题目 ID，例如 `weekday-4c4f4bab.cpp`、`saddle-point-5fef17c8.cpp`。常见中文题名用本地关键词命名；无法识别时用 `problem-序号`。不调用 AI、不额外消耗模型额度。仍使用原有题目 ID 与文件 URI 关联，旧文件不强制改名，已有文件不覆盖。

新文件自动保存下面的模板，注释中的版本由插件自动填入；无工作区时创建带模板的未命名 C++ 文档，需要自行保存。

```cpp
//Powered by Grid-Code connector plugin v0.2.13!
#include <iostream>

using namespace std;

int main(){

    return 0;
}
```

## AI 对话历史（0.2.14）

点击底栏 **网格·历史**，或执行命令“编程网格：对话历史”。提示/交流页底部的“题目连接与保存位置”也提供入口。快捷提问和简短提示继续使用原有入口。

- 左栏按题目查找，右栏选择该题的对话并阅读记录；题目与对话名称都可以搜索。
- 旧记录自动归为“历史交流”“简短提示”“参考解答”，不改写或删除原文件。
- 支持新建独立对话、重命名、归档/恢复。勾选“显示已归档”可找回；归档只改变可见性，不取消已发出的生成任务。
- 在底部输入追问，或点击某条回答的“追问这条”；Ctrl / Cmd + Enter 发送。各对话分别保存未发送草稿。
- 追问使用该条消息保存时的题目和代码；点击“查看当时的代码”可核对。当前编辑器的后续修改不会自动加入历史追问，需要针对新代码提问时使用原有“网格·交流”。新建对话以该题历史中保存的快照为起点。
- 历史按每批 30 条加载，可加载更早记录；“导出已加载记录”保存 Markdown。回答保留 Markdown、公式和代码高亮/复制。
- 只有发送追问才调用 AI；打开、搜索、归档和查看代码均为本地操作。生成中只读取本机任务状态，不重新发送问题。

历史数据来自本机插件，不导入 ChatGPT 网站聊天。对话元信息保存在私有 data/conversations，原始回答仍在 data/hints。为控制上下文大小，追问最多携带沿父消息链最近 6 条已完成回答，最新回答最多 8000 字符，其他每条最多 2000 字符；完整原文仍可在历史页阅读。

## 反馈对照、自定义快捷键与源码模板（0.2.15）

### 反馈显示

“网格·评测”顶部保留网站完整原文，并新增“复制网格原文”。下方辅助对照读取网格明确给出的 Std/Out 差异片段，或 Standard Output / Your Output 段落；前者标注 Case/行号（网站提供时）与片段范围。

- 标准输出与实际输出并排展示；窄窗口上下排列。
- 空格显示为 ·，制表符为 ⇥，换行为 ↵，回车为 ␍，不换行空格为 ⍽；只影响辅助视图。
- 标色范围为首尾相同文本之间的差异区段，不是新的判题结果。
- 网站只提供片段时不补全输出；省略号形式的标准输出段落不生成对照。输出段落中的排版换行可能来自网页，仍以网格原文为准。
- 每次最多展示 20 组对照，每栏最多 12000 字符，原文独立保留。没有可靠对照字段时直接阅读上方原文。
- 页面可临时关闭对照或空白字符标记；默认值在设置的 gridCoach.feedback.showComparison / visibleWhitespace 中修改。

### 自定义快捷键

执行“编程网格：自定义快捷键”，或点击评测页底部同名按钮，打开已筛选本扩展命令的 VS Code 键盘快捷方式页。双击命令录入按键，可查看冲突，也可删除默认绑定。现有保存、提示、交流、历史等命令同样可以绑定。

默认按键采用两段式：先按 Ctrl+Alt+G，松开后按下表第二个键；macOS 为 Cmd+Alt+G。

| 第二个键 | 操作 |
|---|---|
| T | 测试代码：网格判题，使用默认空 stdin 模式 |
| S | 正式提交当前代码 |
| J | 打开测试与提交页 |
| P | 打开题目原文 |
| H | 打开对话历史 |
| ← / → | 上一题 / 下一题 |

测试、提交和打开评测的默认快捷键只在 C++ 编辑器或网格评测页生效；其他默认快捷键在可信工作区生效。执行命令仍会检查题目关联和源码。测试/提交复用页面按钮流程与忙碌检查，不通过另一套接口，也不运行本机判题。快捷键中的 T 固定使用网格判题；需要手工输入时使用页面选项与按钮。

### 自定义源码模板

最方便的方式：执行“编程网格：编辑源码模板”，或点击评测页底部“编辑源码模板”。首次会在 VS Code 扩展私有目录创建可编辑的 source-template.cpp，并把绝对路径写入用户设置 gridCoach.source.templateFile。编辑后 Ctrl+S 保存，新题源码就会使用保存的内容。

也可以清空 templateFile，改用 gridCoach.source.template 设置中的文本行数组（每项一行）。模板文件非空时优先读取文件；已有源码和已关联题目不会被覆盖。文件必须是 UTF-8 文本。模板有误或无法读取时会提示并停止创建，修好后重试切题。

支持的占位符：

| 占位符 | 内容 |
|---|---|
| ${pluginVersion} | 已安装的扩展版本 |
| ${problemTitle} | 题名 |
| ${problemId} | 完整题目 ID |
| ${problemNumber} | 当前题单序号 |
| ${fileName} | 实际创建的源码文件名 |
| ${date} | 北京时间 YYYY-MM-DD 日期 |

示例模板文件：

~~~cpp
//Powered by Grid-Code connector plugin v${pluginVersion}!
// ${problemTitle} | ${date} | ${fileName}
#include <iostream>

using namespace std;

int main(){

    return 0;
}
~~~

“编程网格：预览源码模板”会打开一份未保存的预览，使用当前题目信息和 preview.cpp 作为示例文件名，不创建题目项目文件。占位符仅做文本替换，不执行代码或脚本；未知占位符保持原样。题名建议放在注释内。

## 账户额度（0.2.17）

底栏显示 **额度·5h 已用 xx%**，点击打开独立详情页。也可执行“编程网格：查看账户额度”或“编程网格：刷新账户额度”。详情包含各额度池、窗口长度、已用/剩余比例、北京时间重置时间和查询时间。设置 gridCoach.usage.showStatusBar 可隐藏底栏入口。

数据来自当前本机 Codex 登录账户的官方 account/rateLimits/read 接口，包含其他 Codex 窗口的共享消耗，不能归因为本插件单独用量。100% 表示用完一个额度窗口，不是运行时长。多个额度池不相加，也不把非 300 分钟窗口换算为 5h。不展示缺乏精确依据的历史累计消耗。

流程：VS Code → 本机连接 → 独立 Codex 只读连接 → 账户额度接口 → 本机内存 → 底栏/详情页。此操作不发起 thread/start 或 turn/start，不发送题目/源码，不生成回答，不读取或展示登录令牌。查询复用既有本机登录；API Key 账户或旧版 Codex 可能不提供套餐额度。

启动时与每 5 分钟读取，手动刷新在 15 秒内合并/缓存以避免重复查询。数据只留在当前窗口内存中，不写进项目或仓库；重置时间已到或查询失败时保留旧数据并提示待更新，不能把未知当成零消耗。

安装 0.2.17 后执行 **Developer: Reload Window**；Chrome 无需重载。尚未实际登录查询或进行界面联调。

接口依据：[OpenAI Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。

## 切题自动跟随与页面布局（0.2.18）

在 Chrome 已连接的编程网格 IDE 中切题后，等待新题原文读取完成，VS Code 会自动打开该题已关联的 C++ 源码，并更新“题目原文”页。没有对应文件时，复用英文命名和自定义模板创建；已有文件与未保存编辑不覆盖。没有打开项目文件夹时使用未命名 C++ 文档；多个项目文件夹或多个关联候选可能需要选择。

VS Code 内的题单/上一题/下一题继续执行网页导航和源码切换。网页发来的切题通知则只触发源码跟随，不再次导航浏览器，不自动测试或提交。重复刷新同一题不重复抢源码焦点；快速连续切题会在绑定和打开前检查当前网页题目，失败提示显示在题单下方，可从题单重新选择目标题目。

原题网址和“在浏览器查看原题”移到题干、题单的最下方，顶部只显示题名和简短连接状态。安装 0.2.18 后执行 **Developer: Reload Window**；Chrome 无需重载。尚未实际进行网页切题联调。
