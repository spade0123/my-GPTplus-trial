题库难度按保存的通过率快照分为：基础 ≥70%，常规 50%–70%，进阶 30%–50%，较难 <30%（各区间下界包含、上界不包含）。题面数值仍默认隐藏，点击“查看通过率”才读取实时官方提交统计。百练题库快照按人数比，NOI 快照按提交次数，二者不能直接比较；实时统计与快照日期、口径可能不同。题库算法范围仍保留原来的上限。

提示、完整解答和交流默认使用 GPT-6.1 Sol / **high**，后台逐次分析默认 xhigh。在右上角“更多”中点“模型设置”即可分别更换模型与推理强度；也可按 Ctrl+Shift+P，执行“OpenJudge：模型与推理强度”。选项来自本机 Codex 实际清单，保存后新请求生效。已入队交互保留请求时的配置；已生成历史保留。定期总结的执行模型由 Codex 计划任务单独控制。

右上角“更多”中的“历史版本”可以查看、比较、复制或导出本题已保存代码，导出只创建新文件。快照提示显示题号、保存时间和文档版本；代码继续修改后会标注旧内容对应保存时的版本。测试区下方可展开“自定义测试与本机限制”，没有预期输出时只展示运行结果；输出差异可查看首个不同字符的位置及空白符。

在 Chrome 打开百练或 NOI OpenJudge，在 VS Code 写 C++。右下角状态栏保留三个按钮：**测试运行 / 提示 / 交流**。

源码取自当前 VS Code 编辑器，包括尚未保存到源码文件的修改；题面和可见的评测信息由独立 Chrome 扩展只读采集。记录保存在本机程序目录的 `data/`，不写 Chrome，不上传 GitHub。

## 安装

1. 下载仓库的 `openjudge-vscode` 分支；在根目录安装 Node.js 依赖：`npm ci --ignore-scripts`。
2. 安装 Node.js 22+、C++ 编译器和已登录的 Codex。本机程序通过 Codex 账户生成回复，会使用相应额度。
3. 在项目根目录运行 `install-openjudge.ps1`，可通过 `-NodePath`、`-CodexPath`、`-CompilerPath` 显式指定工具路径。该脚本只注册 `edu.openjudge.cpp_coach`，不替换原北大插件。
4. 在 Chrome 扩展管理中“加载已解压的扩展程序”，选择本分支的 `extension` 目录；在 OpenJudge 页点击 **OpenJudge · VS Code 连接** 图标。
5. 在 VS Code 扩展菜单选择“从 VSIX 安装”，安装本分支 `dist/` 内的 `openjudge-cpp-coach-0.5.5.vsix`。Windows 会从独立连接的注册信息自动发现本机程序；也可运行命令“OpenJudge：选择本机程序目录”。
6. 打开 C++ 文件，Chrome 打开题目后，左侧自动显示题面，保存对象跟随题号。同一个 `main.cpp` 可反复复用，各题源码、问答和报告分开。升级后需刷新 Chrome 扩展并重新加载 VS Code 窗口。

源码项目构建安装包：在根目录运行 `node tools/build-vscode.mjs`，再在本目录使用官方 `@vscode/vsce` 的 `vsce package --no-dependencies`。旧浮窗源码与组件保留作历史参考，0.5.5 不调用它们。

## 使用

- **测试运行**：先记录本轮完整代码、题面和运行证据，再在临时副本上编译并运行样例，对照预期和实际输出。窗口可收起，也可直接提交到 OJ；后台继续分析，当前源码文件不被改写。
- **提示**：每次打开都保存当前代码并更新提示，保留历史解答和问答，交流区默认折叠；相同配置和内容复用已有提示。需要绕过复用时，点“用当前模型重新生成”。较新的同题请求会替代尚未开始的旧提示，源码与请求历史仍保留。
- **交流**：直接展开提示面板内的交流区域。输入框在历史上方，新问答排在旧内容上方，问题与当时源码一同保存；收起后可继续，已发送问答可从磁盘恢复。
- **给出解答**：代码放最前，无注释、使用紧凑运算符写法，保留 `using namespace std;`；高亮和复制保持原始代码内容。
- **提交详情**：在 Chrome 打开当前题目的 `/solution/编号/` 页面。可在面板中选择其标签；未显式选择时尝试读取同题集内当前打开的活动提交详情。
- **收起**：关闭本题教练面板并回到源码；草稿文字先保存到本机，不保存到源码文件。

## 兼容范围与限制

| 功能 | 适配方式与边界 |
| --- | --- |
| 三按钮 | 使用 VS Code 右下角状态栏；三个功能使用编辑区内的插件标签页，首次与源码并排，切换自动关闭上一页，最多保留一个。 |
| 题面 | 分别保留描述、输入、输出、样例输入和样例输出。样例缩进不被去掉；题面提示不混入执行输出。 |
| 代码 | 每次动作重新读取本次编辑器缓冲区，不依赖磁盘旧版本，不自动回填参考答案。 |
| AC/WA/CE/TLE 等 | 读取网页可见状态；只有题号、提交详情和提交源码与当前完整代码一致时才关联，AC 才触发本机完成归档。源码不可见时标“未核对”，不会假报 AC。 |
| 登录 | 需要在 Chrome 自己登录 OpenJudge。连接只读已有登录态的页面；不会处理密码或绕过登录。 |
| 运行输出 | 读取提交页公开显示的编译错误/评测状态。网站没有显示的标准输出、隐藏测试和运行输入无法读取；不会拿题目样例冒充实际输出。 |
| VS Code 终端 | 不自动读取其他扩展的 Output、Debug Console 或终端滚动历史；这类数据没有统一可靠的读取接口。静态诊断会单独标注。 |
| 测试与提交 | 提示面板内“运行样例”在本机临时目录编译运行；“提交到 OJ”首次读取实际编译器选项，再点击发送；刷新只查询。均须明确点击。 |
| 历史与报告 | 历史存本项目 `data/`，报告默认 `reports/`，可用本机 `native/report-location.json` 改为桌面文件夹；与原版数据分开。报告只保留逐题讨论，在同一 HTML 按北京时间追加更新，包含原题、本人源码、debug、问答和必要参考程序；数学、Markdown 与代码均渲染。阅读目录只放 HTML，任务状态放在阅读目录外。 |
| 平台 | 首版以 Windows 桌面版 VS Code + Google Chrome 验证。VS Code 网页版、SSH/容器/WSL 远程文件和其他浏览器不属于已验证范围。 |
| 时延 | 本机先保存，模型在后台流式回复；完整提示或完整程序不能保证 3—5 秒结束。恢复历史不重复调用模型。 |

原版本仍位于仓库的 `mcp` 分支；本版本只在 `openjudge-vscode` 分支开发。

[VS Code Webview API](https://code.visualstudio.com/api/extension-guides/webview)、[终端读取 API 的范围](https://code.visualstudio.com/api/references/vscode-api#TerminalShellExecution)。

## 运行样例与 OJ 提交（0.2.0）

- 每次点状态栏“提示”都会保存点击时完整代码、题面和运行信息，包括已有历史对话或面板已打开时；不必另点快捷保存。历史对话继续保留，恢复历史本身不重复调用提示模型。
- **运行样例**：按题目例子输入运行当前代码，在插件里分栏显示预期/实际输出、耗时、源码哈希及编译错误。空白差异单独标记；样例一致不等于 OJ AC。编译限时 8 秒、运行限时 2.5 秒、合计输出限制 64 KiB。
- **提交到 OJ**：读取已登录 Chrome 中本题官方表单及实际 C++ 编译器选项；首次选择编译器，再点击发送当前完整代码。源码快照先写本机；每个点击事件最多发送一次。
- **刷新本次结果**：只查询该次提交，保留提交编号和当时的源码。即使文件已改动，旧提交结果也不会覆盖新代码。正在评测时可自动查询最多 30 次；无法唯一确定编号时停止猜测，可在 Chrome 打开这次提交详情后再刷新。
- 正常使用不碰网站 localStorage、sessionStorage、IndexedDB，也不改网站函数。只有明确提交所需的代码框/编译器字段被赋值，不执行网站的自定义提交脚本。
- 运行与提交记录分别存放 `data/sample-runs/`、`data/oj-submissions/`，一并纳入本机学习报告。样例执行与提交网络耗时独立于模型响应速度。
- 真实登录页需通过表单核对；接口或字段无法识别时会停止并说明，不尝试其他写入地址，不自动重试不确定的提交。开发只用自拟代码和模拟服务验证，不替用户发送测试作业。

## 状态栏测试运行（0.2.2）

右下角保留三个按钮：测试运行、提示、交流。测试运行先保存代码，再测试题目样例；即使缺少样例、编译失败或运行超时，已经确认保存的代码仍保留。结果显示在插件自己的面板，不覆盖源文件、不调用网站测试按钮。

提示面板中的运行样例、提交到 OJ、给出解答等按钮保持原样。原快捷保存命令保留为兼容入口，状态栏不再显示该按钮。

## VS Code 内置题库与提交体验（0.3.0）

- 左侧“经典题库与题面”内置百练 237 题、NOI 100 题；支持搜索题号/题名/知识点、按平台和难度筛选，以及上一题/下一题。前后切换遵循当前筛选结果的题单顺序。
- 打开方式：左侧 OpenJudge 图标，或命令面板运行“OpenJudge：打开经典题库（337 题）”。选择题目即可打开；不需要复制网址。Chrome 连接扩展须已连接。
- 切题只导航 Chrome 中的题目标签并读取原文；已有提交表单不会被题库导航覆盖，VS Code 源码和未保存修改保持原样，不触发保存或模型调用。不同题目仍按站点、题集和题号独立保存。
- 提示中的交流入口放在最上方；点击“提交到 OJ”立即把本次提交状态移到面板顶部并滚动到该处，其他提示按钮保留。
- 从 VS Code 提交后，只有题号、完整源码匹配且真实评测为 AC，才在本机保存结果后关闭本次对应的官方提交页。题目页保留；若提交页已改写代码、已有更新提交或换成其他页面，则保留它。重复刷新不会重复提交。
- 题库为 2026-10-20 核对的快照，NOI 已排除 1.x。百练通过率按目录人数比，NOI 非 1.x 按统计页 AC/总提交次数；90% 及以上均排除。难度改按通过率快照划分，算法范围上限仍保留。
- 升级需刷新 Chrome 中“OpenJudge · VS Code 连接”，再重新加载 VS Code 窗口。浏览器权限没有增加，不清缓存、不改站点函数或 VS Code 设置。

## 测试窗口操作（0.3.1）

独立“测试运行”窗口右上角有“收起”和“提交到 OJ”。收起会回到源码，已经保存的代码和测试记录保留；正在进行的保存与测试继续执行。

提交会读取点击时最新完整代码，不会复用旧样例测试时的源码。首次核对编译器，选择后再次点击才发送；提交状态立即移到顶部，支持反复刷新，刷新不重复提交。真实 AC 在题号和源码核对后保存到本机，并只关闭该次对应的 Chrome 提交页。提示里的交流入口保持在上方。

从 0.3.0 升级到本版只需安装新版 VSIX 后重新加载 VS Code 窗口，无需刷新 Chrome 连接。网站脚本和存储、VS Code 设置与源码文件均不改动。

## 窗口复用与提交基本信息（0.3.2）

VS Code 中最多保留一个独立测试运行窗口。再次点击或更换题目都复用它；先前测试继续保存各自记录，返回较晚的旧结果不会覆盖新一轮。窗口保留“收起”“提交到 OJ”和刷新结果。右下角三个状态栏按钮固定显示，不随插件面板或题库焦点消失。

打开提示时默认折叠交流区；点击“交流”再展开，历史和草稿不删除。新的问答放在以前内容上方。

两种窗口的 OJ 结果均列出提交编号、题号、提交人、内存、耗时、编译语言及提交时间；字段只使用这次官方详情，缺失或冲突显示“未提供”。提交记录保存在本机，不上传 GitHub。网站 AC 仍需题目和源码匹配，才关闭对应提交页。

升级到 0.3.2 后需重新加载 VS Code，并在 Chrome 扩展管理刷新一次连接扩展（2.2.1），以启用新增字段读取；没有新增网站权限，也不操作网站存储。
