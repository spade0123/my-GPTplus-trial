# 北大计算概论 C++ 学习教练 MCP

个人用的 C++ 作业学习工具，包含 MCP 服务、Chrome 扩展和 Windows 本机连接程序。在北大编程平台 IDE 页面保存自己的代码，后台分析缺点、优化方向和需要补学的知识，并比较同题多次修改和 debug 过程。

**作业源码、修改历史、运行记录、分析报告和 AC 最终归档全部保存在本机。本项目没有 GitHub 作业上传功能。GitHub 仓库只用于发布工具程序与文档。**

## 使用流程

1. 在 Chrome 打开北大题目 IDE：`https://programming.pku.edu.cn/probset/<题集ID>/<题目ID>/ide.do`。
2. 右下角有三个入口：**快捷保存**、**提示**、**交流**。首次可从“提示 → 核对详情 / 保存记录”检查题面五部分、运行信息和完整源码。
3. **快捷保存**直接读取当前编辑器并保存，放入后台分析，不展开详情。需要修改备注时，打开详情填写并点击“保存过程版本”。确认保存后即可继续修改、保存其他代码或切换题目。
4. 点击平台自己的“提交程序”时，扩展独立记录本次提交的代码。识别到与该提交对应的 AC 后，在本机生成最终代码、README 和 debug 总结。
5. 在面板查看本题修改时间线、后台报告和本机最终归档状态。报告失败可以重试，源码仍然保留。

过程保存和最终归档是两条独立流程。AC 到达时，即使编辑器已改成下一版，也只归档当时提交的代码。后台生成报告不会占住保存按钮；最后归档也不会覆盖过程记录。

### 即时提示与代码交流

| 按钮 | 作用 |
| --- | --- |
| 快捷保存 | 每次重新读取当前题目、代码与运行界面，保存并安排完整报告；不打开详情页 |
| 提示 | 保存请求时的完整快照，先核对题目目标并做本地初筛；后台根据解题思路对照现有代码，给出差距、局部修改方向和验证方法 |
| 交流 | 打开本题对话窗口；每次“发送并保存”都保存当前源码、问题和运行信息，回复归入同一道题的交流记录 |

在编辑器选中代码再提问，或直接问“第 12 行是什么意思”“这里为什么越界”。交流会结合本次源码、选中片段与最近六轮已保存问答。不同题目的对话相互独立；刷新后打开交流窗口可读取本题最近 30 轮记录。原始提问与回答完整保存在本机，界面和模型只限制本次加载的上下文长度。

为缩短等待，提示和交流先使用**浏览器本地规则**：对实际源码中的常见边界、输入问题，以及 `getline`、`find`、`substr` 等接口给出初步反馈。本地无法判断的问题会明确说明需要后台模型分析，不伪装成已经完成推理。随后自动补充模型回复；此时可以继续编辑、快捷保存或发送下一条问题。交流、普通提示和完整报告分别运行，长提示和长报告不会挡住交流入口、首次本地反馈或保存。

**1.6.2 的题目定向提示：** 深入提示先说明“本题目标 → 解题方向 → 与当前代码的差距”，再指出具体行号、原因、局部改法和下一步。以题面、约束和样例推导正确逻辑，优先帮助现有程序完成题目，不用泛泛的语法或函数介绍代替算法指导。验证建议尽量包括符合题意的最小输入、预期输出与当前代码的手算过程；没有实际运行时会明确标注。浏览器即时部分只做题目目标核对与本地初筛，不冒充已经完成答案推导。

若本机保存过**本人同一道题、题面一致且与判题 AC 关联的提交源码**，后台会选取最近的合格版本辅助比较；不会把模型以前生成的程序、其他题的 AC 或仅含“AC”字样的运行输出当成参考答案。源码哈希不符或文件缺失时不使用该参考。参考代码最多带入 16,000 个字符，截断会明确标注。没有合格参考时按题意推导，并标明依据，不能声称取得官方答案或隐藏测试。允许不同的正确算法，只给必要的局部代码，不默认重写完整答案。旧版完整提示在你再次点击“提示”时会重新排队升级，原回复另存在该任务的 `previousReports` 中；已经升级的同版本提示继续复用。

**1.6.0 的交流加速：** 模型正文边生成边显示，约每 0.3 秒读取一次新内容，不再等整篇完成才展示。打开交流窗口时预先建立本机连接，不发送题目、不调用模型生成答案；连接空闲约 90 秒后退出。问答只带当前完整题面、源码、运行信息与最近六轮精简问答，不反复附带整份报告、历史源码和递归提示记录；普通交流不先启动编译器。首句优先直接回答问题，需要长篇讲解时可明确提出。

交流通过 Codex App Server 的私有 stdio 连接，使用同一 Codex 登录与 `gpt-6.1-sol` 的 `low` 推理强度；模型请求走 HTTP 流，避免当前环境的 WebSocket 反复重连。每轮使用临时只读会话，不在 Codex 侧栏新建聊天；禁用其他 MCP、shell、浏览器、插件和代理执行，所有工具审批请求均拒绝。只在这一个后台进程中调整连接配置，不修改使用者全局 Codex 设置，也不切换到额外付费的加速档位。完整报告继续使用 `xhigh`。

首条反馈以 **3 秒内**为目标；若页面读取超过 **4.5 秒**，界面结束等待并显示未读取成功的状态，允许重试。这个时限不代表已经给出有效模型答案，网络、额度与模型服务也可能使深入回复超过 5 秒。深入回复超过 60 秒会记为失败并提供重试，本地初步反馈与已确认保存的记录仍保留。模型提示不替代编译、测试或在线判题。

“提示”只凭**同题且源码一致**的实际提交证据识别 AC，不从样例、执行输出中的“AC”或旧版本推断。确认当前源码 AC 时仍保存并生成学习分析，但不再生成排错提示；修改后的源码需重新核对。交流不受 AC 限制，可以继续讨论已通过程序的写法与优化。

每次请求的时间、源码版本、题面、运行界面、问题、本地初步反馈和后台答复均有关联记录。即使源码内容相同，多次不同问题仍分别保留。后续报告据此分析卡点与 debug 过程，结合后来的实际修改和评测判断建议是否被采纳，不把建议直接当作已经修复。旧报告不会因一次提问自动重写；定期总结会读取新增的交流证据。

### 自动草稿保护与“修改后无法测试”

**自动释放缓存（1.6.1，默认开启）：** 打开北大题目 IDE 页面后自动检查，之后约每 30 秒检查一次；网站写入存储、其他标签页修改存储或发生真实 `QuotaExceededError` 时也会触发检查。按全部网站 `localStorage` 的键和值长度估算，达到 **2,097,152 个 UTF-16 代码单元（约 4 MiB）**的保守预警线时，自动释放可重新下载的题面、题集缓存。这是预警估算，不是浏览器实际配额的保证；真实容量错误即使低于预警线也会触发处理。多标签页共用后台清理任务并限制检查频率，失败后至少等待约 60 秒再重试，避免反复备份和清理。

清理前，将符合 `problem_<32位ID>`、`problemlist_<32位ID>` 的缓存完整备份到**扩展后台自己的 IndexedDB**，等待写入完成并回读核对，成功后才删除网站里的对应条目。备份失败或核对不一致时不开始删除；核对期间已改变的缓存条目保留。只处理这两种可重新下载的缓存，不清理源码、源码内容缓存、草稿、提交、账号、Cookie、运行输入或本机报告，不修改编辑器、不自动刷新，也不调用模型。缓存和草稿分别存储，自动备份不会占用 `chrome.storage.local` 的草稿配额。IndexedDB 本身仍可能发生空间不足或不可用，遇到此类错误会显示提示并保留网站缓存。如果空间主要由源码占用、已没有可清理的题面缓存，会提醒另存当前代码，不自动删除源码，也不能保证消除其他原因造成的网站故障。

自动清理成功后**静默运行，不弹出“已自动备份并清理”浮窗**，条数和估算释放空间仅记录在详情的“网站题面缓存清理”中。备份失败或没有可安全清理项目的容量故障仍会提示。

仍可手动执行：**提示 → 清理题面缓存**，或进入 **核对详情 / 保存记录 → 网站题面缓存清理 → 备份并清理题面缓存**，采用相同的先备份后清理流程。手动清理完成后显示结果，在详情里点击 **下载最近一次清理备份** 可导出 JSON。内容和来源页面均相同的缓存复用已有备份，变化后的快照独立保存，不覆盖旧备份；备份键以 `pku-site-cache-backup-` 开头。旧版存于 `chrome.storage.local` 的备份仍可读取，不自动删除。备份不进入模型分析或 Chrome 账号同步，卸载扩展、清理扩展存储或浏览器回收数据可能使其丢失，重要备份请下载保存。备份可供核对，网站会在下次访问时重新获取题面。

**1.5.1：题面空白、只剩标题框架，测试按钮没有反应。** 如果控制台报 `QuotaExceededError`，并且键名是 `problem_<题目ID>`，表示网站在缓存题面时已用尽 `localStorage`。网站原流程先写缓存，再显示题面、载入代码并绑定测试按钮，因此缓存写入异常会把后续初始化一起中断；点“显示”只展开空框，刷新又会重新遇到相同错误。

扩展在页面初始化前，仅对当前北大 IDE 的 **`problem_<32位ID>` 和 `problemlist_<32位ID>` 可重新获取的缓存**增加保护：原写入确实报 `QuotaExceededError` 时，不写这一次缓存，继续使用网站已获取到的题面完成原来的显示和初始化。空间充足时仍正常缓存。这层即时保护本身不删除旧键；后台自动清理另按上面的备份流程执行。它不改动备份、源码、提交、账号或会话；这些其他写入的失败不会被这个保护吞掉。跳过题面缓存也不代表当前源码已保存。

旧源码、草稿和本机报告继续保留，**无需手动清空网站数据或重新安装扩展**。更新后先把屏幕上未保存的代码复制到文件，再去 `chrome://extensions` 重新加载“北大 C++ 学习教练”（当前版本 **1.6.2**），然后刷新题目页，即会开启自动检查。题面初始化的即时保护已用网站原有脚本在隔离环境复现验证：此前题面与代码为空、测试未初始化；保护后正常加载，只有主动点击测试才发起请求。自动清理另行验证备份、范围限制及源码保留。

在平台自己的“编辑修改”状态下，扩展会在停止输入约 **0.6 秒**后，把编辑器中的代码单独备份到本机的 Chrome 扩展存储。草稿按**题目页面和当前账号**区分，每题保留最近 **10 个不同代码版本**；未写完的代码、暂时无法编译的代码也可以备份。它不生成报告、不消耗模型额度、不自动提交，也不会覆盖手动“保存过程版本”的完整修改历史。修改发生后立即关闭页面或浏览器，最后几次输入仍可能来不及确认写入；重要版本请另存 `.cpp` 或手动保存。

查看或取回草稿：打开右下角学习教练面板 → **自动草稿备份与恢复** → **查看本题草稿**，选中版本后可以下载 `.cpp`，或主动点击**将这份草稿恢复到网站编辑器**。查看和刷新页面不会自动覆盖编辑器；恢复前先独立备份屏幕上的当前代码。如果恢复前又有新修改，则停止恢复，避免覆盖刚输入的内容。

北大 IDE 的公开脚本会在发送测试请求前先写入网站的 `localStorage`。每次不同代码可能新增一份内容缓存；存储空间用尽时，这一步可能抛出 `QuotaExceededError`，造成“旧版能测、修改后点测试没反应，刷新又回到旧代码”。这个情形已用原网站脚本在隔离环境复现，**不能据此断定每个测试故障都是存储不足**。

扩展仅针对**网站备份函数抛出的 `QuotaExceededError`**提供保护：独立草稿确认写入成功后，才继续用户刚点击的原测试或提交流程；不会清空网站数据、删除旧记录、绕过登录或改变判题结果。等待备份期间又修改了代码，会提示重新点击；备份失败会明确显示错误，停止补救，不假报保存成功。其他类型的异常保持原来的行为，需要依据实际报错排查。

独立草稿使用 `chrome.storage.local`，与网站的 `localStorage` 分开，不依赖本机模型连接。扩展存储仍有容量限制，**卸载扩展会移除这些自动草稿**；手动保存到项目 `data/` 的过程版本不受此影响。草稿不上传 GitHub，也不放入 Chrome 账号同步存储。更新此功能后需要在 `chrome://extensions` 重新加载已安装扩展，再刷新 IDE；**刷新前先把编辑器里的代码复制到本地文件**。

如果仍不能测试，请先备份代码，再在开发者工具 Console 查看第一条红色报错。不要首先清除网站数据，以免删除可恢复的草稿。

## 报告的六个板块

1. **代码中普遍的冗余部分**：标出重复判断、重复计算、无效变量等，结合行号给局部简化；正确性与边界问题优先说明。
2. **输入手段的优化与拓展**：针对题目格式比较 `cin`、`getline`、字符读取、EOF 等，解释空白、换行、多组输入和流同步的适用条件。
3. **可替代原始实现的函数与关键字**：对照手写实现、标准函数或语言特性、等价片段和使用边界，帮助减少不必要的实现时间。
4. **更简洁的解法与参考程序**：原实现繁琐或存在值得学习的简洁思路时，给出符合题意和所选 C++ 标准的完整参考程序及解释；没有实质改进或题目信息不足时如实说明。
5. **头文件、函数与关键字分类拓展**：按实际头文件和用途整理函数表，语言关键字单独归类；选最多三个优先补学主题并给练习与掌握标准。
6. **时间与空间复杂度及优化方向**：定义输入规模，推导原解与参考解的开销、瓶颈、优化收益及代价，并给边界验证建议。

新生成的单次报告和最终复盘使用固定六板块结构。各板块结合真实代码差异、修改备注和运行/判题证据解释 debug 过程；区分已证实问题、待验证风险与风格建议。参考程序没有实际运行或评测时会明确标注。

### 汇总报告的阅读顺序

手动全量复盘与定期汇总报告采用“**先共性总结，后逐题分析**”的顺序。前面的六个板块只归纳整体问题、优化方法、适用条件、补学重点和复杂度方向；具体题目的行号、反例、debug 对比和完整参考程序集中放在末尾的逐题附录。

HTML 的逐题区域使用独立折叠项：**默认收起，仅显示题目标题；可以同时展开多道题**，不会因打开一题而关闭另一题。打印或导出 PDF 时自动展开全部题目，打印结束后恢复原来的展开状态；PDF 保留完整内容，不受屏幕上的折叠状态影响。

逐题附录直接呈现保存的题面与本人源码，不需要先点击“题目页面”或打开单独源码文件。每道题按下面的顺序阅读：

1. **原题目**：题目描述（含提示与约束）、关于输入、关于输出、例子输入、例子输出，五部分分开排版。
2. **我的源码（本次保存）**：原样展示实际保存的 C++ 代码，与题面和样例放在同一处；排版版在宽屏上并排展示，窄屏上依次排列。
3. **分析与改进**：具体诊断、代码行号、真实修改与 debug 证据、复杂度和建议验证。
4. **参考程序与说明**：有实质改进时提供，并与本人的原始源码明确区分。原题已经列在该题开头，不重复粘贴。

Markdown 原文同样包含题面、样例、本人源码和分析，不依赖外部页面才能阅读。样例保留空格与换行；执行输出、运行提示、错误和判题记录不混入例子输出。保存快照中缺失的图片、公式或约束会明确标记，不补造。

扩展面板支持 Markdown 标题、**加粗**、*强调*、`行内代码`、嵌套列表、表格、引用、链接、代码块和 LaTeX 公式。行内公式支持 `$...$` 与 `\(...\)`，独立公式支持 `$$...$$` 与 `\[...\]`。Marked、KaTeX 与数学字体随扩展本地提供；原始 HTML 作为文字显示，图片显示替代文本。下载报告仍保留原始 Markdown，已有报告可以直接使用新的渲染方式查看，内容结构保持其生成时的版本。

题面、源码、语言标准、运行信息、修改备注和评测结果都一致的记录，会在时间线和复盘中合并为一条，并标明次数与原记录编号；只有时间或平台提交编号不同不算内容变化。只要备注、运行输出或判题证据不同，就保留独立记录。重复快照复用已有分析；原始提交关联与发生位置继续保留，因此 A → B → A 的实际修改顺序仍可复原，AC 仍对应自己的提交。

## 安装

## 后台任务与定期总结

Native Messaging 连接负责快速保存和查询。交流、普通提示和完整报告各有独立的队列与隐藏进程，同一交流队列内按发送顺序处理；首次本地反馈和保存不等待模型队列。交流连接在窗口打开时预连接，并在空闲约 90 秒后退出。状态包括 `queued`、`running`、`failed`、`complete`，只有 `complete` 才表示模型回复或报告完成。逐步生成的 `partialAnalysis` 和首段到达时间 `firstTokenAt` 会保存，连接失败时也保留已生成部分，但不会当作完整答案。下次打开或查询排队任务时会恢复中断的后台进程。电脑关机期间不运行。

可在 Codex 设置北京时间**每周三 11:30、每周五 08:30**的定期总结（当前作者使用的计划）。两个时间分别配置任务，读取相同的本地记录，并共用所选报告根目录下 `summary-state.json` 中上次成功总结的截止时间，汇总此后新增的保存、修改、提交和分析，避免重复统计。第一次没有历史状态时回看最近七天。

任务中应明确上述报告格式：前六个板块先做共性总结，最后按题目合并展示完整题面、独立样例、原始源码、分析和参考程序。通过 `review_history`、`problem_timeline` 的 `assistance` 读取提示与交流证据；若标记 `truncated`，需要读取本机 `data/assistance/` 与对应 `data/hints/` 的原始记录。新增问题和新完成回复即使源码相同，也属于新增学习证据；不得因去重源码而漏掉。每次生成保留 Markdown 原文及渲染后的 HTML，写入报告专用文件夹的独立子目录，并维护根目录 `index.html`。报告成功写入后再更新共享进度；没有新增内容时保持安静。其他使用者需要自行在 Codex 配置任务及报告路径；MCP 安装脚本本身不创建应用定时任务。
