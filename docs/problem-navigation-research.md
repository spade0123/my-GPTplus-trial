# 编程网格题目列表与快速切题可行性调研

日期：2026-10-21。范围：实际使用的 `https://programming.pku.edu.cn`。本文保留初始调研；0.2.11 已根据用户补充的真实菜单 HTML 实现题单与快速切题，尚待登录环境完整联调。

## 0.2.11 实现更新

用户进一步提供了真实结构：`ol > li#li_<32位题目ID> > a[href="../<题目ID>/ide.do"]`；当前项有 `currentproblem` 类，`a` 没有 href。这确认可以直接读 DOM，不必模拟悬停或猜测切题 API。

- `extension/grid-navigation.js` 优先读取包含当前题的 `ol`，按子元素顺序取题名、题号、题目 ID，并以当前 URL 补足当前题链接。其次尝试同题集合法链接，以及题集页面的只读 HTML。
- `extension/grid-worker.js` 实现 `list_problems` / `activate_problem`，只接受本次发现的同题集目标，复用或新开 IDE 标签，并等待目标题面可读。
- 本机消息白名单与 `src/vscode-service.js` 同步增加两个操作；服务再次校验题集和目标题面。
- `vscode-extension/problem-navigation.js` 将题单、搜索、上一题/下一题放入题面页。列表默认折叠，避免占满题面；上一题/下一题按列表位置计算，不遍历网站的提交页面。
- `vscode-extension/problem-navigation.cjs` 管理题目与源码映射。已有明确关联的源码优先复用，新题在工作区的固定题集目录创建独立空白 `.cpp`；多候选文件或工作区时由用户选择，没有工作区则用未命名文档。原文件留在编辑器中，未保存改动保持原样。
- 导航开始前处理文件选择；Chrome 确认题面后才显式关联源码，完成后打开编辑器。中断标记写入工作区私有存储；关联未完成时禁止新测试/提交，重选题目或显式关联可恢复。
- 读取列表、切题不调用 AI，不触发网站测试或正式提交；计时器继续运行。未读取浏览器编辑器草稿到新文件，旧网页标签仍保留。

更新要求：Chrome 连接、本机程序与 VS Code 均为 0.2.11；需重载 Chrome 扩展和 VS Code 窗口。当前验证范围为语法检查和打包，未运行测试或向网站发起真实切题。初始表中菜单 href/结构未知的问题已由用户 HTML 解决；首次加载时是否已有菜单、其他题集布局和网站登录重定向仍需现场观察。

## 结论

**技术上可行，现有浏览器连接和题面同步可以复用。** 尚需确认登录页面里菜单链接和加载方式，才能实现可靠的列表抓取。无需让 AI 识别题目，也无需把登录凭据交给 VS Code。

## 可复用的浏览器能力

Chrome 官方提供 [scripting.executeScript](https://developer.chrome.com/docs/extensions/reference/api/scripting) 读取授权页面，以及 [tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs) 查询、创建和导航标签。当前扩展已声明 `scripting` 与本站 host permission，可沿用这条架构；预计无需增加“所有网站”访问范围。

```text
登录后的网页菜单 / 当前题集页面
  → Chrome 扩展读取题号、题名、链接与顺序
  → 已有 Native Messaging 本机桥接
  → VS Code 题目原文页显示列表与搜索
  → 用户选择题目
  → Chrome 打开或复用目标 IDE 标签
  → 页面就绪通知
  → VS Code 同步题面并打开已关联源码
```

登录继续由用户在 Chrome 完成。读取列表与切题不发送源码给 AI，也不触发测试或正式提交。

## 建议的实现顺序

1. **先复刻 IDE 菜单**：按网页顺序展示题号和题名，标记当前题；提供刷新和题名搜索。只收集菜单区域的题目，不扫描整页所有链接，以免把其他作业混进来。
2. **识别真实菜单数据**：先检查现成的隐藏 DOM；若首次悬停才加载，再核对该区域的加载动作或只读请求。没有读到列表时明确提示，不猜测题目 ID。
3. **补足当前题**：当前菜单项可能是无链接灰色文本，可用当前 IDE 已知题目标识补入，再去重、核对题集。
4. **加入快速切题**：优先激活已打开的目标题 IDE；没有则新开标签，保留原网页草稿。若需要复用同一标签，须先处理网页编辑器未保存草稿。
5. **增加上一题/下一题**：完整列表存在时按列表顺序导航；“提交程序”页的下一题链接作为辅助来源，不靠连续点击遍历整个题集。

建议新增 `list_problems`、`activate_problem` 两个浏览器动作，并同步更新本机消息白名单与 VS Code 服务。当前只支持已打开 IDE 的 `tabs`，不等于上述动作已实现。普通提交页目前也不在 `grid-worker.js` 的 IDE 发现范围内，读取它的下一题需要单独增加受限页面识别。

## 切题时的数据一致性

- **源码按题保存映射**：用题集 ID + 题目 ID 映射文件 URI，不用题名当唯一键。首次遇到新题时创建或选择源码文件，不把上一题代码默认绑定过去。
- **处理未保存改动**：切换文件前保留或保存当前文档；不覆盖已有源码。不因单纯切题触发“快捷保存”所带的 AI 分析。
- **等目标题加载完成**：显示正在切换，题面标识核对通过后才切换操作上下文；加载失败时显示失败状态，不沿用旧题面冒充新题。
- **请求与结果各自绑定题目**：测试、提交使用点击时捕获的题目标识、源码指纹与回执；旧题的晚到结果仍归旧题。切换进行时禁用新发起的测试/提交，不自动重发任何请求。
- **范围校验**：只接受本站、当前题集、已发现的合法题目地址。目录读取和“下一题”均不能执行提交动作。菜单只能提供题目列表；不额外推断没有显示的 AC 状态。
- **计时器独立**：当前计时器按工作区保存，切题继续计时；以后如要逐题统计，应新增题目 ID 维度，不能把本轮计时默认为单题耗时。

## 开始实现前最少还需要的页面信息

有条件时在用户自己的浏览器观察一次菜单：菜单项真实链接/HTML、首次悬停是否新发请求，以及“下一题”的真实链接。无需账号信息、Cookie 或整页个人数据。现有两张截图已足够支持方案判断，但不足以写死选择器并承诺适配成功。
